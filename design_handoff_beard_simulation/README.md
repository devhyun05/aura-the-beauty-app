# Handoff: AURA 수염 제거 플로우 (beard-simulation)

## Overview
AURA 앱 `수염 제거` 탭의 전체 플로우 구현 인계 문서.
목적 선택 → (수염 분석: 3단계 설문) → 촬영 → 생성 로딩 → Onyx Glass 결과 → (수염 분석: 상세 보고서), 그리고 실패/재촬영 화면까지 포함한다.

원 기획 요청서: `docs/beard-simulation/CLAUDE_DESIGN_BEARD_SIMULATION_REQUEST_KO.md` — 이 문서와 충돌 시 요청서의 금지사항(§2, §12)이 우선.

## About the Design Files
`prototype/AURA Beard Flow.dc.html`은 **HTML로 만든 디자인 레퍼런스(인터랙티브 프로토타입)**다. 브라우저에서 열면 전체 플로우가 동작한다. 이 HTML을 그대로 이식하지 말 것 — **Expo React Native + TypeScript + React Navigation + Tamagui + 기존 AURA 테마 토큰/공용 컴포넌트로 재구현**하는 것이 과제다. 파일 안에 템플릿(마크업+인라인 스타일)과 로직 클래스(상태·타이머·핸들러)가 모두 들어 있으므로 정확한 수치·타이밍은 소스에서 직접 확인 가능하다.

`prototype/assets/*.png` 4장은 **중립 플레이스홀더**(원본 + 강도 3단계)다. 실제 앱에서는 촬영 원본 + 생성 엔진 결과 3장으로 대체된다. 데모/스토리북용으로만 재사용.

## Fidelity
**High-fidelity.** 색·타이포·간격·워딩·인터랙션 모두 확정 시안. 단, 수치는 CSS px 기준(390×844 논리 해상도) → RN dp로 1:1 매핑. 전역 theme 파일을 바꾸지 말고 오닉스 값은 `features/beard-simulation` 로컬 토큰으로 추가할 것 (기존 `colors/spacing/radius/typography/shadows` 비례 준수).

## 프로토타입에서 목업/생략된 것 (구현 시 실제 연동 필요)
프로토타입과 이 문서 사이 차이가 아니라, **프로토타입 자체가 시뮬레이션인 지점**이다. 실제 구현에서 채울 것:
- **카메라**: 실시간 프리뷰·품질 감지 없음 — 상태 문구가 ~950ms 간격 자동 순환하는 목업. 실제로는 얼굴 정렬/밝기 감지에 연결. 기존 `CameraFaceCaptureScreen` 재사용.
- **앨범 선택**: 프로토타입은 토스트(`데모 사진으로 진행해요`) 후 바로 로딩으로 진행 — 실제는 이미지 피커.
- **카메라 전환**: 토스트만 표시되는 데모.
- **권한 상태**: 카메라·앨범·사진 저장 권한 요청/거부 화면이 프로토타입에 없음 — 기존 권한 패턴으로 추가 (§10 상태 목록 참조).
- **일부 강도 단계만 제공 가능한 상태**(엔진이 3장 전부 못 만든 경우) 미구현 — 해당 스톱 disabled 처리 필요.
- **생성 지연/실패, 저장 실패**: Tweaks 토글로만 시뮬레이션 — 실제 엔진/미디어 라이브러리 오류에 연결.
- **모션 감소·햅틱**: 명세만 있고 프로토타입은 미구현 (`useReducedMotion`, `expo-haptics`).
- **설문 step2 부위 선택**: 기획서의 "하관 실루엣 탭 영역"은 생략하고 텍스트 칩만 사용(기획서상 선택 사항, 칩이 접근성 기본형). 실루엣을 추가해도 칩은 유지.
- **`사진 처리 및 삭제 기준` 링크**: 토스트 목업 — 실제 정책 문서(`DATA_POLICY_KO.md` 기반 화면)로 연결.
- **저장/클립보드**: 브라우저 API 사용 — `expo-media-library` / RN Clipboard로 대체.

## Navigation / State
- 스택: PurposeSelect → Survey(3 step 내부 상태) → Camera → Generating → Result → Report. Failure는 Generating의 대체 결과.
- 뒤로: Survey→step-1/Purpose, Camera→Survey(분석)/Purpose(보정), Result ✕→Purpose(탭 루트), Report←→Result.
- 상태: `path('analysis'|'photo')`, 설문 답변(뒤로 가도 유지; 새 사진/삭제 때만 초기화), `intensity(0|1|2)`, `dividerPct`(강도 변경에도 유지), `holding/pinned`, `saving/savedOnce`, `toast`, 로딩 단계/지연, 보고서 활성 앵커.
- 강도 변경: 이미지 크로스페이드 300ms (RN: 3장 프리로드 후 opacity Animated).

## RN 구현 노트 (HTML→RN 매핑)
- 글래스: `expo-blur` BlurView + 반투명 bg + 1px border. blur 미지원/저성능 시 투명도+경계만으로도 성립해야 함.
- Before/After 클리핑: `clip-path` 대신 **overflow:hidden 컨테이너(width=divider%) 안에 화면 폭 고정 이미지** 패턴. 드래그는 PanResponder/Gesture Handler로 스크롤보다 우선 캡처.
- 스크린 블렌드 광 밴드(`mix-blend-mode:screen`)는 RN 미지원 → 반투명 그라디언트(expo-linear-gradient) + 낮은 opacity 흰 레이어로 근사.
- 스캔 모션: Reanimated 루프(translateY + 시머는 translateX 그라디언트). `useReducedMotion` 시 정적 표현.
- 저장: `expo-media-library` — 현재 강도 결과 이미지 1장 저장, 권한 거부 UI 필수.
- 햅틱: `expo-haptics` light 1회 (hold 진입 시).
- Safe area: 하단 패널/CTA는 safe inset 위, 홈 인디케이터와 겹침 허용(패널 bottom 14 기준).
- 접근성: 원본 보기 버튼 accessibilityLabel `원본 보기 — 누르고 있는 동안 원본을 보여드려요. 짧게 탭하면 고정돼요`; 슬라이더에 3스톱 버튼이 이미 대체 조작 역할; 모든 터치 타깃 ≥44.
- 아이콘: 전부 `lucide-react-native` 범위(scan-face, image, eye, chevron-left, x, more-vertical, copy, trash, check, refresh 계열). 새 라이브러리 금지.
