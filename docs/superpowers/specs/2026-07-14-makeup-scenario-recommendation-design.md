# 메이크업 시나리오 추천 설계

작성일: 2026-07-14

## 1. 목적

사용자가 정형화된 카테고리를 고르는 대신 재미있는 문구를 구경하며 자신이 원하는 메이크업을 발견하게 한다. 선택한 시나리오와 자유 입력, 기존 얼굴 분석 및 취향 데이터를 바탕으로 AI가 필요한 정보만 추가로 질문한 뒤 다음 세 가지를 함께 추천한다.

- 완성 메이크업 룩
- 부위별 메이크업 방법
- 사용할 제품과 대체 제품

첫 화면의 성공 기준은 가장 빠른 검색 시작이 아니라, 사용자가 문구를 탐색하다가 "오늘은 이거다" 싶은 마음을 발견하는 것이다.

## 2. 설계 원칙

- 첫 화면은 선택 폼이 아니라 스크롤 가능한 메이크업 아이디어 피드로 보이게 한다.
- `데일리`, `스페셜`, `유니크` 같은 큰 카테고리를 첫 진입의 필수 선택으로 사용하지 않는다.
- 상황극, 장난스러운 문구, 프리미엄 문구를 섞되 각 문구의 의미는 명확해야 한다.
- AI는 프롬프트와 기존 사용자 정보에 이미 있는 내용을 다시 묻지 않는다.
- 추가 질문은 보통 1~2회, 최대 3회로 제한한다.
- 선택지로 표현되지 않는 답은 모든 질문에서 자유롭게 입력할 수 있다.
- 마지막 질문에서는 별도 턴을 만들지 않고 `+ 조건 추가`를 펼쳐 추가 요청을 함께 제출할 수 있게 한다.
- 결과는 하나의 정답이 아니라 안전한 선택, 더 과감한 선택, 예상 밖의 발견을 함께 제공한다.
- 사용자가 직접 작성한 최신 요청을 AI 추론이나 과거 취향보다 우선한다.
- 다른 팀원이 소유한 아우라딘 구현은 수정하거나 내부 코드에 결합하지 않는다.

## 3. 첫 화면: 오늘의 메이크업 시나리오

### 3.1 화면 구조

상단에는 제목, 자유 입력창, 분석 정보 사용 상태를 둔다. 그 아래에는 30~36개의 시나리오 문구를 세로 스크롤로 노출한다.

```text
오늘, 어떤 내가 되어볼까요?

[ 원하는 느낌이나 상황을 직접 들려주세요        → ]
[ 내 분석 결과 반영 중 ]

오늘의 메이크업 시나리오

[ 오늘의 나를 가장 아름답게 ]
[ 5분 했는데 30분 공들인 척 ]
[ 출근길 그 사람에게 오늘은 인사할 거야 ]
[ 요즘 무드, 나답게 ]
...

[ 새로운 시나리오 보여줘 ]
```

첫 뷰포트에는 6~8개가 보이고 나머지는 자연스럽게 스크롤한다. 작은 칩 30개를 한 화면에 억지로 넣지 않는다. 긴 문구와 짧은 문구, 강조 카드와 일반 카드를 섞어 잡지의 헤드라인처럼 리듬을 만든다.

### 3.2 문구 구성

한 세션에서 보여주는 30~36개는 다음 출처를 혼합한다.

- 검수된 기본 문구: 30%
- 상황극 및 캐릭터 문구: 25%
- 사용자 취향 기반 개인화 문구: 20%
- 계절, 시간대, 운영 중인 트렌드 문구: 15%
- 평소와 다른 도전 및 AI 와일드카드: 10%

말투 기준은 다음과 같다.

- 상황극 및 서사형: 약 40%
- 장난스럽고 친근한 말투: 약 30%
- 감각적이고 프리미엄한 말투: 약 30%

모든 문구를 한 말투로 합성하지 않는다. 서로 다른 말투의 카드가 피드 전체에서 번갈아 등장하게 한다. 첫 6개 안에는 세 가지 말투가 모두 포함되어야 한다.

### 3.3 대표 문구 예시

```text
오늘의 나를 가장 아름답게
5분 했는데 30분 공들인 척
출근길 그 사람에게 오늘은 인사할 거야
요즘 무드, 나답게
전남친 결혼식, 내가 제일 평온한 사람
빛과 사진에 아름다운 룩
중계 카메라에 잡힐 야구장 여신룩
꾸안꾸는 충분히 했고 오늘은 잘꾸
낯설지만 나다운 변화
느좋, 느낌 좋은 미대생룩
어제 잘 잔 사람처럼 출근하기
평소보다 한 단계 대담하게
점 찍고 돌아온 드라마 16부 엔딩
AI야, 오늘 내 얼굴에 서사 좀 줘
새벽 두 시 네온 아래에서 제일 예쁜 얼굴
부잣집 고명딸 음대생룩
사진첩 첫 장 예약
약속 없어도 조금 특별하게
```

강한 연애나 복수 서사는 전체의 일부로만 사용한다. 외모 비하, 불안 자극, 신체 변화 보장, 타인에 대한 혐오 표현은 생성하거나 노출하지 않는다.

### 3.4 문구 데이터 모델

화면 문구와 실제 추천 입력을 분리한다.

```ts
type MakeupScenarioPrompt = {
  id: string;
  displayText: string;
  seedPrompt: string;
  intentTags: string[];
  tone: 'narrative' | 'playful' | 'premium';
  source: 'curated' | 'personalized' | 'trend' | 'wildcard';
  personalizationReason?: string;
  expiresAt?: string;
};
```

예를 들어 `5분 했는데 30분 공들인 척`을 선택하면 실제 요청에는 `짧은 시간에 완성할 수 있지만 정교해 보이는 메이크업`이라는 의미가 전달된다. 화면 문구만으로 추천 의미를 추론하지 않는다.

### 3.5 생성과 개인화

전체 검수 문구 풀은 100개 이상 유지하고, 한 번 진입할 때 30~36개를 편집해 제공한다. AI는 새로운 문구를 만들거나 기존 문구를 사용자 말투에 맞게 변형할 수 있지만, 생성 결과는 다음 검사를 통과해야 한다.

- 탭했을 때 추천 방향이 명확하다.
- 같은 의미의 문구가 한 세트에 중복되지 않는다.
- 외모 비하, 민감 정보 추정, 과장된 효능 보장이 없다.
- 반드시 구체적인 `seedPrompt`와 구조화된 의도 태그를 가진다.
- 트렌드 문구에는 만료 시점을 둔다.

생성 실패나 네트워크 오류 시 검수된 로컬 문구 풀을 즉시 사용한다. 첫 화면 진입을 AI 생성 응답으로 막지 않는다.

개인화에는 얼굴 분석 및 퍼스널컬러, 저장한 룩, 최근 선택한 시나리오와 결과를 사용한다. 화면 상단에 `내 분석 결과 반영 중` 상태를 표시하고 사용자가 끌 수 있게 한다. 분석 정보는 소프트 선호로만 사용하며 사용자의 현재 요청을 제한하는 하드 조건으로 사용하지 않는다.

## 4. 적응형 질문 흐름

### 4.1 질문 결정

시나리오 또는 자유 입력을 받은 AI는 다음 정보가 이미 있는지 판단한다.

1. 원하는 인상과 변화
2. 상황과 장소
3. 도전 강도
4. 시간과 숙련도
5. 예산, 구매 채널, 보유 제품 및 회피 조건

추천 결과에 미치는 영향이 크고 아직 모르는 항목 하나만 다음 질문으로 선택한다. 질문은 보통 1~2회, 최대 3회다. 정보가 충분하면 질문 수를 줄인다.

### 4.2 질문 화면

- 선택지는 4~6개다.
- 선택지끼리 의미가 겹치지 않아야 한다.
- `AI가 골라줘` 또는 의미상 동등한 위임 선택지를 제공한다.
- 모든 질문 하단에 선택지 대신 사용할 수 있는 자유 입력란을 제공한다.
- 앞선 질문은 선택 즉시 다음 단계로 이동할 수 있다.
- 마지막 질문은 선택 후 바로 이동하지 않고 명시적인 `추천받기` 버튼을 보여준다.

마지막 질문의 기본 구조는 다음과 같다.

```text
어느 정도까지 과감해도 괜찮나요?

[ 조금만 다르게 ]
[ 한눈에 달라 보이게 ]
[ 오늘은 과감하게 ]
[ AI가 골라줘 ]

[ + 조건 추가 ]                         [ 추천받기 ]
```

`+ 조건 추가`를 누르면 같은 화면 안에서 입력창만 펼친다. 새로운 대화 턴으로 계산하지 않는다.

```text
[ 예: 글리터 제외, 립 강조, 15분 이내 ]

                                        [ 추천받기 ]
```

추가 조건은 앞선 선택과 함께 한 번에 제출한다. 빈 입력은 허용하며 추가 설명 문구를 길게 노출하지 않는다.

### 4.3 우선순위

충돌하는 조건은 다음 순서로 처리한다.

1. 안전, 알레르기 및 피부 회피 조건
2. 마지막에 직접 입력한 추가 조건
3. 현재 질문에서 사용자가 직접 선택하거나 작성한 답
4. 최초 시나리오 또는 자유 프롬프트
5. 과거 선택, 저장 기록, 얼굴 분석 및 퍼스널컬러 기반 추론

조건을 지키면서 결과를 만들 수 없으면 조건을 조용히 무시하지 않고 어떤 조건 때문에 후보가 부족한지 알린다.

## 5. 추천 결과

### 5.1 세 가지 룩

결과는 역할이 다른 세 가지 룩으로 구성한다.

1. `anchor`: 얼굴 분석과 현재 요청에 가장 안정적으로 맞는 룩
2. `bold`: 선택한 시나리오를 더 선명하고 과감하게 표현한 룩
3. `discovery`: 평소 취향 밖이지만 어울릴 가능성이 있는 발견형 룩

세 룩은 색상만 조금 다른 중복 결과가 되어서는 안 된다. 각 룩의 차이를 제목과 한 줄 설명으로 분명하게 표현한다.

### 5.2 룩 상세 정보

각 결과는 다음 정보를 제공한다.

- 룩 이름과 대표 이미지
- 이 룩을 추천한 이유
- 반영된 조건
- 베이스, 아이, 브로우, 치크, 립의 부위별 방법
- 단계별 적용 순서
- 예상 소요 시간과 난이도
- 핵심 제품과 대체 제품
- 저장하기
- 기존 AR 가이드로 적용하기
- `더 자연스럽게`, `더 힙하게`, `다른 색으로`, `제품만 바꾸기` 재조정

MVP의 대표 이미지는 검수된 레퍼런스 룩 이미지 또는 서버가 제공하는 룩 이미지 URL을 사용한다. 사용자 얼굴 합성 이미지를 추천 생성의 필수 조건으로 두지 않는다. 사용자가 룩을 고르면 기존 AR 적용 흐름으로 연결한다.

### 5.3 결과 데이터 모델

```ts
type MakeupLookRecommendation = {
  id: string;
  role: 'anchor' | 'bold' | 'discovery';
  title: string;
  summary: string;
  imageUrl?: string;
  reasons: string[];
  appliedConditions: string[];
  durationMinutes: number;
  difficulty: 'easy' | 'medium' | 'advanced';
  steps: MakeupRecommendationStep[];
  products: MakeupRecommendationProduct[];
};

type MakeupRecommendationStep = {
  area: 'base' | 'eye' | 'brow' | 'cheek' | 'lip';
  instruction: string;
  order: number;
};
```

## 6. 시스템 경계와 데이터 흐름

### 6.1 모바일 경계

새 경험은 메이크업 룩 추천이라는 독립 기능 경계로 둔다. 새 코드는 `features/makeup-recommendation` 아래에 두고, 공용 `shared` 계층의 테마 토큰, UI 및 `requestBackendJson`만 재사용한다. 아우라딘 전용 디자인 시스템, 타입, 화면, 서비스 또는 상태를 import하지 않는다.

모바일의 논리 단위는 다음과 같다.

- 시나리오 피드: 문구 로드, 개인화 상태, 새 세트 요청
- 추천 세션 컨트롤러: 시작, 질문 응답, 조건 추가, 취소 및 만료
- 질문 화면: 선택지, 자유 답변, 마지막 질문의 조건 추가
- 결과 화면: 세 가지 룩, 상세 방법, 제품, 저장 및 AR 이동
- 서비스 계층: `requestBackendJson`을 통한 API 호출과 오프라인 fallback 매핑

구체적인 파일 분할은 구현 계획에서 현재 브랜치의 화면과 라우팅 소유권을 다시 확인한 후 정한다. 새 route를 추가할 수는 있지만 기존 아우라딘 route의 컴포넌트, 파라미터 또는 동작은 변경하지 않는다.

### 6.2 아우라딘 수정 금지 경계

아우라딘은 다른 팀원이 소유한 기존 기능이므로 다음 영역은 새 기능 구현 범위에서 제외한다.

- `apps/mobile/src/features/recommendation/screens/AuradinSearchScreen.tsx`
- `apps/mobile/src/features/recommendation/screens/views/`
- `apps/mobile/src/features/recommendation/components/ds/`
- `apps/mobile/src/features/recommendation/services/auradinSearchService.ts`
- 아우라딘이 사용하는 mock, suggestion, attachment 및 타입 계약
- `services/backend/app/api/search_sessions.py`
- `services/backend/app/services/auradin_agent/`
- `services/backend/app/services/auradin_catalog/`
- `data/auradin/` 및 아우라딘 세션 스키마와 설정

기존 코드의 아이디어나 외부 동작을 참고할 수는 있지만 파일을 수정하거나 내부 함수를 import해 결합하지 않는다. 새 기능 때문에 기존 아우라딘 테스트의 기대값을 변경하지도 않는다.

아우라딘의 공개 `/search/sessions` API를 변경 없이 호출하는 black-box 연동은 기술적으로 가능하고 제품 후보 품질에 도움이 될 수 있다. 그러나 이 API는 완성 룩과 부위별 방법이 아니라 제품 검색에 최적화되어 있으며, 새 기능을 다른 팀 소유 서비스에 결합하는 비용이 있다. 따라서 MVP에서는 사용하지 않는다. 향후 팀 소유자와 사용자가 명시적으로 승인한 경우에만 결과 생성 뒤 제품 후보를 보강하는 선택적 adapter로 추가한다.

### 6.3 백엔드 경계

현재 `/search/sessions`와 `auradin_agent`는 구매 가능한 화장품 후보 검색에 최적화되어 있다. 완성 룩, 부위별 방법, 세 가지 룩 역할을 동일한 제품 검색 상태에 억지로 추가하지 않는다.

메이크업 룩 추천은 별도 API, 서비스, 타입 및 저장소 계약을 사용한다. 구현 방식은 프로젝트의 일반적인 인증 및 DB 패턴을 따르되 아우라딘 파일을 수정하거나 내부 구현을 호출하지 않는다.

MVP 제품 추천은 새 기능이 소유하는 검수된 fixture와 adapter에서 제공한다. 이 데이터는 룩별 핵심 제품과 대체 제품을 구조화해 보관하며 아우라딘 카탈로그를 읽거나 복제하지 않는다. 실제 상용 제품 데이터 소스 연결은 adapter 뒤에서 교체할 수 있게 하되 MVP 완료 조건에는 포함하지 않는다.

- 인증된 세션 소유권
- PostgreSQL 또는 메모리 세션 저장
- TTL과 취소
- 구조화된 질문과 답변
- 질문 수 제한
- 결과 생성 실패 시 결정적 fallback
- 새 기능이 소유한 제품 데이터 adapter와 대체 제품 매핑

권장 API 계약은 다음과 같다.

```text
GET  /api/makeup/scenarios
POST /api/makeup/recommendation-sessions
GET  /api/makeup/recommendation-sessions/{sessionId}
POST /api/makeup/recommendation-sessions/{sessionId}/answers
POST /api/makeup/recommendation-sessions/{sessionId}/cancel
POST /api/makeup/recommendation-sessions/{sessionId}/refine
```

세션 시작 요청은 `scenarioId` 또는 자유 `prompt`, 분석 정보 사용 여부와 사용 가능한 리포트 ID를 받는다. 질문 답변 요청은 선택지 또는 자유 답변 중 하나를 받고, 마지막 답변에는 `additionalConstraints`를 함께 받을 수 있다.

```json
{
  "questionId": "q-2-boldness",
  "optionId": "noticeably-different",
  "freeText": null,
  "additionalConstraints": "글리터 제외, 립 강조, 15분 이내"
}
```

### 6.4 전체 흐름

```text
시나리오 피드 로드
→ 시나리오 선택 또는 자유 입력
→ 프로필 사용 동의 상태와 함께 추천 세션 시작
→ 서버가 구조화된 의도와 기존 소프트 선호 병합
→ 정보가 부족하면 질문 반환
→ 모바일이 선택 또는 자유 답변 제출
→ 마지막 답변에는 펼쳐진 추가 조건을 함께 제출
→ 서버가 anchor, bold, discovery 룩 생성
→ 새 기능의 제품 adapter에서 핵심 및 대체 제품 연결
→ 모바일 결과 화면과 AR 진입 제공
```

## 7. 상태 및 실패 처리

첫 화면과 질문 및 결과 화면은 다음 상태를 모두 가진다.

- loading
- empty fallback
- error with retry
- refreshing
- session expired
- partial result

상세 동작은 다음과 같다.

- 시나리오 API 실패: 로컬 검수 문구를 즉시 노출한다.
- 개인화 실패: 개인화 이유를 숨기고 기본 문구 세트를 사용한다.
- 질문 생성 실패: 결정적 기본 질문을 사용하거나 현재 정보로 결과를 생성한다.
- 세션 만료: 기존 프롬프트와 답변을 유지한 채 새 세션으로 다시 시작할 수 있게 한다.
- 일부 룩 생성 실패: 성공한 결과를 먼저 보여주고 부족한 슬롯만 다시 시도한다.
- 대표 이미지 실패: 이미지 placeholder와 텍스트 추천을 유지한다.
- 제품 후보 없음: 룩 방법은 유지하고 제품 영역에 대체 검색 또는 미제공 상태를 표시한다.
- refine 실패: 기존 결과를 유지하고 재시도 메시지만 표시한다.
- 사용자가 이탈: 세션 취소는 best-effort로 처리하고 화면 이탈을 막지 않는다.

## 8. 개인정보 및 안전

- 얼굴 분석과 취향 정보는 명시된 `내 분석 결과 반영 중` 상태에서만 사용한다.
- 사용자가 분석 정보 사용을 끄면 해당 세션과 개인화 문구 생성에 전달하지 않는다.
- AI가 연애 상태, 직업, 경제력, 성격과 같은 민감하거나 사적인 특성을 사용자 데이터에서 추정해 문구를 생성하지 않는다.
- `전남친 결혼식`이나 캐릭터형 문구는 사용자가 선택할 수 있는 창작 시나리오이며 실제 사용자 상태로 저장하거나 단정하지 않는다.
- 제품 추천은 화장품 효능이나 외모 변화를 보장하지 않는다.
- 알레르기나 피부 회피 조건은 다른 미적 선호보다 우선한다.

## 9. 테스트 및 검증

### 9.1 모바일

- 시나리오 30~36개 노출과 첫 6개 말투 혼합
- 중복 의미 및 만료된 트렌드 문구 제외
- 분석 정보 사용 토글과 요청 컨텍스트
- 시나리오 선택 및 자유 입력 세션 시작
- 선택지 답변과 자유 답변 매핑
- 최대 3회 질문 제한 표시 및 상태 전환
- 마지막 질문에서만 `+ 조건 추가`와 명시적 `추천받기` 노출
- 추가 조건이 마지막 답변과 함께 한 번만 전송됨
- 세 가지 결과 역할 및 상세 매핑
- loading, empty, error, retry, 만료 및 partial 상태
- 저장 및 AR 네비게이션 계약
- 모바일 typecheck

### 9.2 백엔드

- 세션 소유권과 TTL
- 시나리오 또는 자유 프롬프트 입력 검증
- 분석 정보가 하드 필터가 아닌 소프트 선호로 병합됨
- 이미 알려진 정보를 다시 질문하지 않음
- 보통 1~2회, 최대 3회 질문 제한
- 선택지와 자유 답변의 상호 배타적 검증
- 마지막 답변의 추가 조건 우선순위
- 조건 충돌 및 후보 부족 시 명시적 복구 응답
- anchor, bold, discovery 결과의 역할 및 다양성
- 부분 생성 및 enrichment 실패 fallback
- 제품과 대체 제품 매핑
- 취소, 만료 및 refine 계약

### 9.3 제품 지표

MVP 비교 대상은 한 세션당 12개, 24개, 36개 문구다. 다음 지표로 노출량을 조정한다.

- 시나리오 선택률
- 첫 선택까지 걸린 시간
- 직접 입력 비율
- 스크롤 깊이
- `새로운 시나리오 보여줘` 사용률
- 질문 중단률과 질문 수
- 결과 저장률과 AR 진입률
- anchor, bold, discovery별 선택률

## 10. MVP 범위와 제외 범위

MVP에 포함한다.

- 자유 입력과 30~36개 시나리오 피드
- 검수 문구 fallback과 새 세트 보기
- 분석 결과 사용 상태와 선택적 개인화
- 최대 3회의 적응형 질문
- 마지막 질문의 인라인 `+ 조건 추가`
- 세 가지 완성 룩, 방법, 제품 결과
- 저장, refine 및 기존 AR 흐름 진입
- 모바일 및 백엔드 핵심 계약 테스트

MVP에서 제외한다.

- 추천 생성 전에 사용자 얼굴에 합성된 이미지를 필수 생성하는 기능
- 캘린더, 연락처 또는 위치의 자동 사용
- 검수되지 않은 실시간 밈을 무제한 노출하는 기능
- 첫 화면 진입을 막는 실시간 AI 문구 생성
- 사용자의 사적 관계나 경제적 배경 추정
- 아우라딘 모바일 또는 백엔드 코드 수정
- 아우라딘 내부 구현 import 또는 공개 API 의존

## 11. 완료 기준

- 사용자는 첫 화면에서 재미있는 문구를 탐색하거나 직접 원하는 메이크업을 입력할 수 있다.
- 시나리오 세트는 상황극, 장난, 프리미엄 말투가 균형 있게 섞인다.
- AI는 기존 사용자 정보와 현재 프롬프트를 이용해 필요한 질문만 최대 3회 한다.
- 마지막 질문에서는 별도 턴 없이 조건을 추가할 수 있다.
- 결과는 서로 구별되는 세 가지 룩과 부위별 방법 및 제품을 제공한다.
- 실패하거나 오프라인이어도 첫 화면과 데모 흐름을 사용할 수 있다.
- 기존 아우라딘 제품 검색과 AR 흐름의 파일 및 동작을 변경하지 않는다.
