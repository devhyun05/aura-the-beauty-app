# AR 눈 메이크업·하이라이터·애교살 확장 설계

## 목표

기존의 룩 트리와 부위별 전용 Unity 렌더러를 함께 사용하는 혼합형 구조를 유지하면서 다음을 구현한다.

- 아이섀도 상·하 standalone 룩을 늘리고, 상단 모양에서 베이스·메인·포인트의 위치 변형을 직접 고를 수 있게 한다.
- 상단 아이섀도 메시를 양쪽 눈의 해부학적 눈꼬리 바깥까지 연장한다.
- 아이라인 상·하 standalone 룩과 상단 스타일을 늘린다.
- 하나로 합쳐진 하이라이터 마스크를 광대·콧대·코끝·눈썹뼈·입술산으로 분리한다.
- 기존 애교살 색 띠·데칼 경로를 제거하고, 자연 볼륨형과 펄 포인트형을 지원하는 전용 렌더러로 다시 만든다.
- 상위 슬롯 룩의 내부 항목은 세부부위 카드로 노출하지 않고, 명시적인 standalone 룩만 노출한다.

## 설계 원칙

룩 선택·저장·컴파일은 기존 공통 룩 트리를 사용한다. 얼굴에 실제로 그리는 단계는 해부학적 요구가 다른 아이섀도·아이라인·애교살·하이라이터의 전용 Unity 경로를 유지한다.

모든 메이크업을 하나의 범용 셰이더로 통합하지 않는다. 대신 공통 데이터 계층은 룩 카탈로그와 레이어 컴파일을 담당하고, 전용 렌더러는 메시·마스크·오클루전·블렌딩을 담당한다.

## 아이섀도

### 상단 모양

`eyeshadowShape` 선택지는 별도 카테고리를 만들지 않고 한 모양 축에 다음 12개를 제공한다. 번호는 React Native와 Unity가 공유하는 enum 값이다.

0. 베이스 전체
1. 베이스 앞쪽
2. 베이스 뒤쪽
3. 메인 앞쪽
4. 메인 중앙
5. 메인 뒤쪽
6. 포인트 앞머리
7. 포인트 눈동자 위
8. 포인트 눈꼬리
9. 크리스
10. 스모키
11. 와이드 그라데

앞쪽·중앙·뒤쪽은 화면 좌우가 아니라 각 눈의 안쪽 눈머리·홍채 중심·바깥 눈꼬리를 기준으로 계산한다. 따라서 양쪽 눈에서 자동으로 미러링된다.

### 눈꼬리 확장

현재 아이섀도 메시가 상안검 속눈썹 라인의 바깥 끝점에서 종료되어 포인트와 메인 뒤쪽 룩도 눈꼬리에서 잘린다. 아이섀도 전용 바깥 확장 구간을 메시 토폴로지에 추가한다.

- 확장 방향은 바깥 눈꼬리에서 관자 방향으로 향하는 상안검 접선과 눈썹 방향을 혼합한다.
- 확장 길이는 눈 반경에 비례해 얼굴 크기와 거리에 따라 함께 변한다.
- 베이스 전체·앞쪽처럼 확장이 필요 없는 모양은 셰이더 가중치로 확장 구간을 0에 가깝게 만든다.
- 메인 뒤쪽·포인트 눈꼬리·스모키·와이드 그라데는 확장 구간을 사용한다.
- 확장 끝은 알파를 0으로 페이드해 색 띠나 직선 경계가 생기지 않게 한다.

### 룩 수

- 아이섀도 상: 12개 standalone 룩. 각 모양이 최소 한 번은 실제 카드에서 사용된다.
- 아이섀도 하: 6개 standalone 룩. 새틴·매트·시머와 밝은 포인트·음영 계열을 포함한다.

기존 눈 전체 룩의 내부 섀도 레이어는 `internal`로 유지한다. 세부부위 선택기에는 새 standalone 룩만 표시한다.

## 아이라인

### 상단 스타일과 룩

상단 `eyelinerStyle`은 기존 윙업(0)·퍼피(1)·롱(2)에 캣(3)·스트레이트(4)·소프트 드롭(5)을 추가해 6개 스타일로 확장한다. 각 스타일은 눈꼬리 각도와 길이의 조합이며 기존 두께·윙 길이·질감·부분·마감 축과 함께 동작한다.

아이라인 상에는 얇은 브라운, 샤프 블랙 윙, 퍼피 브라운, 가로 롱, 꼬리 포인트, 앞머리+꼬리, 스모키 젤, 컬러 펄의 8개 standalone 룩을 제공한다.

### 하단 룩

아이라인 하는 소프트 브라운·딥 브라운·버건디·얇은 점막형·바깥 1/3 포인트·소프트 펄의 6개 standalone 룩을 제공한다. `eyelinerLowerStyle`은 전체 소프트(0), 점막 밀착(1), 바깥 1/3(2)으로 구분하며 하안검 전용 밴드가 강도·색·구간 가중을 렌더링한다.

## 하이라이터

### 부위 분리

기존 `HighlightRegion`의 합성 마스크를 다음 5개 마스크로 분리한다.

- 광대: 좌우 광대뼈 상단
- 콧대: 세로 콧대
- 코끝: 콧대와 독립된 작은 포인트
- 눈썹뼈: 좌우 눈썹뼈 하단
- 입술산: 큐피드보우

React Native 룩 트리에는 `highlightCheek`, `highlightNoseBridge`, `highlightNoseTip`, `highlightBrowBone`, `highlightCupid`를 각각 독립 세부부위로 등록한다. 대응 강도 필드는 `highlightCheekIntensity`, `highlightNoseBridgeIntensity`, `highlightNoseTipIntensity`, `highlightBrowBoneIntensity`, `highlightCupidIntensity`다. 따라서 개별 켜기·끄기와 동시 적용이 가능하다. 색과 마감은 하이라이터 제품의 공통 축으로 유지해 부위 조절이 제품 스타일을 불필요하게 복제하지 않도록 한다.

Unity `FaceMakeup` 경로는 5개 마스크와 5개 강도를 합성한다. 레거시 `highlightIntensity`와 합성 마스크는 기존 저장물 호환을 위해 유지하며, 새 부위 강도가 하나도 없을 때만 레거시 경로를 사용한다.

## 애교살

### 제거 범위

기존 `LowerLidRenderer`와 `LowerLid.shader`에서 다음 애교살 책임을 제거한다.

- 하이라이트·섀도 색 띠 합성
- 애교살 데칼 텍스처와 임포트 강도
- 애교살 마감·시머 처리
- 애교살 두께가 하단 아이라인·아이섀도·컨실러 밴드 높이를 함께 바꾸는 결합

`LowerLidRenderer`는 아이라인 하·아이섀도 하·삼각존·눈밑 컨실러만 담당한다.

### 새 전용 렌더러

새 `AegyoRenderer`와 `Aegyo.shader`는 하안검 랜드마크를 따라 독립 메시를 만든다.

- 상단은 실제 카메라 피부색을 보존한 채 은은한 볼륨광을 더한다.
- 하단은 바로 아래에 넓고 부드러운 음영을 배치해 돌출감을 만든다.
- 광과 음영은 각각 종 모양 프로파일로 페이드하며 두 줄로 칠한 듯한 경계를 만들지 않는다.
- 메시 높이는 눈 폭에 비례하고 `aegyoHeight`로 조절한다.
- 눈을 감거나 추적 신뢰도가 낮을 때 눈 영역으로 번지지 않도록 기존 눈 스텐실과 오클루전 게이트를 재사용한다.

두 렌더링 모드를 제공한다.

- 자연 볼륨형: 피부 루마 기반의 저강도 볼륨광과 부드러운 음영. 펄 입자는 없다.
- 펄 포인트형: 자연 볼륨형 위에 중앙 집중 미세 펄을 추가한다. 펄은 눈꼬리까지 띠처럼 이어지지 않는다.

새 필드는 `aegyoMode`(0 자연 볼륨, 1 펄 포인트)와 `aegyoShadowIntensity`다. 기존 `aegyoIntensity`, `aegyoColor`, `aegyoHeight`, `aegyoShimmer`는 새 렌더러의 광·색·높이·펄 강도로 재사용한다.

standalone 룩은 내추럴 소프트·로지 볼륨·도톰 볼륨의 자연형 3개와 샴페인 펄·핑크 펄·라일락 펄의 펄형 3개, 총 6개를 제공한다. 구 저장물은 `aegyoFinish === 3`이면 펄형, 나머지는 자연형으로 정규화한다. `aegyoStyleIntensity`와 애교살 데칼 경로는 더 이상 렌더링하지 않으며 새 UI에서도 노출하지 않는다.

## 데이터 흐름과 호환성

1. 세부부위 카드가 독립 `LookDef`를 선택한다.
2. 룩 트리가 부위별 파라미터를 `FilterParams`와 아이섀도 레이어 배열로 컴파일한다.
3. React Native 브리지가 Unity 메시지를 전송한다.
4. Unity 컨트롤러가 아이섀도·아이라인·애교살 전용 렌더러와 하이라이터 마스크 강도에 값을 전달한다.

새 숫자 필드는 생략 시 0으로 정규화한다. `eyelinerLowerStyle`과 `aegyoMode`의 0은 각각 전체 소프트와 자연 볼륨이다. 기존 전체 룩과 저장물은 계속 렌더링되어야 한다. 새 하이라이터 강도 중 하나라도 0보다 크면 5부위 경로를 사용하고, 모두 0이면 레거시 `highlightIntensity`와 합성 마스크를 사용한다. 이전 애교살 저장물은 위 규칙으로 새 모드에 매핑하되 데칼 파일 자체는 더 이상 렌더링하지 않는다.

## 테스트

- 룩 카탈로그 계약: 아이섀도 상 12·하 6, 아이라인 상 8·하 6, 애교살 6, 하이라이터 5부위를 검증한다.
- 범위 계약: 상위 눈 룩의 내부 섀도·라이너가 세부부위 카드에 노출되지 않음을 검증한다.
- 브리지 계약: 새 하이라이터 강도와 확장된 모양·스타일 값이 Unity 메시지에 보존됨을 검증한다.
- Unity 소스 계약: 아이섀도 확장 토폴로지, 12개 모양 분기, 5개 하이라이터 마스크, 새 애교살 전용 렌더러 연결을 검증한다.
- 수치 계약: 아이섀도 뒤쪽 모양의 외곽 끝이 원래 눈꼬리보다 바깥이며 끝 알파가 0임을 검증한다.
- 회귀 검증: 모바일 타입체크, 기존 AR 룩·가이드·브리지 계약, Unity 배치 컴파일을 실행한다.

## 후속 제안 규칙

작업 중 다른 메이크업에서 동일한 구조적 문제가 발견되면 이번 구현에 임의로 추가하지 않는다. 사용자에게 현재 동작, 사용자 영향, 권장 변경, 예상 범위를 별도 제안한다. 단순 코드 정리나 취향성 변경은 제안 대상으로 올리지 않는다.
