# AR 피부 보정·파운데이션 백탁·룩 계층 노출 설계

## 목표

AR 메이크업에서 피부 보정 체감은 강화하되 피부의 입체감과 주요 경계는 보존한다. 톤업 파운데이션은 현재 로지 룩과 비슷한 밝기 범위 안에서만 작동하게 해 얼굴이 허옇게 뜨는 현상을 막는다. 룩 선택기에서는 전체 룩, 부위 룩, 세부부위 룩을 각자의 계층에서만 노출한다.

## 현재 동작과 문제

- 로지 룩은 `skinSmoothing: 0.55`, `skinBrightening: 0.3`을 사용하며 `foundationIntensity`는 0이다. Unity의 브라이트닝은 원본 RGB에 약한 게인과 오프셋을 더하므로 사용자가 적절하다고 확인한 기준이다.
- 스크린스페이스 파운데이션은 제품색과 사용자 피부색의 HSV 명도 차를 직접 더한다. 밝은 제품색과 높은 강도가 결합하면 로지보다 훨씬 밝아져 얼굴이 백탁처럼 뜬다.
- 피부 결 보정은 12탭 bilateral 커널을 사용하지만 최대 강도의 반경과 range 완화가 사용자가 원하는 강보정 수준에 못 미친다.
- 시스템 룩은 상위 룩을 구성하기 위한 내부 `sub` 정의도 전역 라이브러리에 저장한다. `subDefsForRegion()`은 해당 세부부위를 포함하는 모든 `sub`를 반환하므로 `로지 아이` 같은 상위 부위 룩의 내부 아이라이너가 아이라인 세부부위 카드에 섞인다.

## 설계

### 1. 피부 결 보정 강화

기존 `skinSmoothing` 계약인 0..1과 UI 슬라이더는 유지한다. 기본 룩의 0이 아닌 피부 보정값은 약 0.07~0.10 올려 룩 선택 직후에도 이전보다 한 단계 강하게 보이게 한다. 값 0은 계속 완전한 no-op이다.

Unity 셰이더에서는 입력 강도를 그대로 선형 반경으로 쓰지 않고 후반부가 크게 증가하는 곡선으로 변환한다.

- 중간 강도에서는 기존 대비 약 15~25% 넓은 커널을 사용한다.
- 최대 강도에서는 현재 약 3배인 반경 상한을 약 5배 수준으로 확장한다.
- 최대 강도에서는 luma range 허용폭도 넓혀 모공과 저대비 잡티가 확실히 평균화되게 한다.
- 눈, 눈썹, 입술, 헤어라인과 배경을 제외하는 기존 마스크 가중치는 유지한다.
- 미세 그레인 재주입은 유지해 최대 보정에서도 고무 피부처럼 보이는 현상을 줄인다.

기본 룩 강화와 슬라이더 곡선 강화는 독립적으로 적용한다. 따라서 룩 선택 직후에는 소폭 강화되고, 사용자가 슬라이더를 끝까지 올렸을 때만 강보정 구간에 진입한다.

### 2. 로지 기준 파운데이션 명도 가드

파운데이션의 색상·언더톤·균일도 보정은 유지하고 밝기 결과만 제한한다. 고정 상수 하나로 shade 차이를 잘라내는 대신, 현재 카메라 픽셀에 로지의 `skinBrightening: 0.3` 공식을 적용했을 때의 명도를 픽셀별 최대 허용 명도로 사용한다.

처리 순서는 다음과 같다.

1. 기존처럼 파운데이션 제품색과 사용자 피부색에서 hue, saturation, value 보정량을 계산한다.
2. 파운데이션 강도와 피부 마스크를 적용한 후보색을 만든다.
3. 후보색의 명도가 같은 카메라 픽셀에 로지 브라이트닝을 적용한 기준 명도를 넘으면, hue와 saturation을 유지하면서 명도만 기준 안으로 축소한다.
4. 제품색이 더 어두운 경우의 음의 명도 이동은 기존 범위 안에서 허용한다.

이 방식은 밝은 피부 픽셀을 추가로 날리지 않으며, 어두운 피부에서도 고정된 흰색 목표로 끌어올리지 않는다. 파운데이션을 선택해도 색조와 피부 균일도 차이는 남지만 밝기만 로지 수준을 넘지 않는다.

### 3. 룩 계층별 선택기 노출 계약

`LookDef`의 `level: 'sub'`만으로는 내부 구성용인지 독립 선택용인지 알 수 없으므로 세부부위 선택기 노출 메타데이터를 추가한다.

- `internal`: 상위 전체/부위 룩을 구성하기 위한 내부 정의. 세부부위 카드에 노출하지 않는다.
- `standalone`: 특정 세부부위에서 직접 선택하도록 만든 룩. 해당 세부부위 카드에만 노출한다.

규칙은 다음과 같다.

- 내장 전체 룩을 분해해 만든 `sub`는 모두 `internal`이다.
- 눈, 립, 피부, 눈썹, 렌즈 등 복합 부위 룩의 자식 `sub`도 `internal`이다.
- 아이라인 하, 애교살, 마스카라, 하이라이터 등 세부부위를 위해 별도로 저작한 룩만 `standalone`으로 표시한다.
- 사용자가 세부부위 룩으로 직접 저장한 정의는 `standalone`이다.
- 기존 저장 데이터에 메타데이터가 없으면 시스템 소유 `sub`는 안전하게 `internal`, 사용자 소유 `sub`는 기존 사용성을 위해 `standalone`으로 해석한다.
- `subDefsForRegion()`은 `standalone` 정의만 반환한다. `regionDefsForSlot()`과 전체 룩 선택은 영향받지 않는다.

따라서 `로지 아이`의 내부 아이라이너는 아이라인 카드에서 사라지고, 아이라인 전용으로 만든 룩만 남는다.

## 데이터 흐름

1. React Native 룩 선택기가 계층에 맞는 정의만 조회한다.
2. 선택된 룩은 기존 `setSlotRegion()` 또는 `setSubRegion()` 경로로 트리에 적용된다.
3. `flattenTree()`와 `compileLayers()`는 기존 계약을 유지한다.
4. `FilterParams`가 기존 브리지로 Unity에 전달된다.
5. Unity는 강화된 smoothing 곡선과 로지 기준 luminance guard를 적용한다.

브리지 필드와 새 UI 컨트롤은 추가하지 않는다.

## 테스트와 검증

- 룩 라이브러리 계약 테스트
  - `eyelinerUpper` 조회 결과에 로지/로즈골드/스모키 등 상위 눈 룩의 내부 자식이 없어야 한다.
  - 아이라인 하, 애교살 등 독립 세부부위 룩은 계속 조회되어야 한다.
  - 슬롯 전체 룩과 전체 얼굴 룩 목록은 기존과 같아야 한다.
  - 메타데이터가 없는 사용자 세부부위 룩은 계속 노출되어야 한다.
- 피부 프리셋 계약 테스트
  - 기존 룩의 0이 아닌 `skinSmoothing` 값이 승인된 강화 범위에 있어야 한다.
  - 원본/직접 룩의 0은 유지되어야 한다.
- 셰이더 계약 검증
  - 0 강도는 기존과 동일한 no-op이어야 한다.
  - 중간 강도보다 최대 강도의 유효 반경 증가폭이 더 커야 한다.
  - 파운데이션 후보 명도가 로지 기준 명도를 넘지 않아야 한다.
- 실행 검증
  - 모바일 TypeScript typecheck와 관련 계약 테스트를 실행한다.
  - Unity 배치 컴파일을 실행한다.
  - 실기기에서는 로지, 밝은 톤업 파운데이션, 결 보정 0/중간/최대, 눈→아이라인 세부부위 카드 목록을 비교한다.

## 비범위

- 얼굴 형태 보정, 가이드 렌더링, 다른 메이크업 부위의 색·마감은 변경하지 않는다.
- 새 UI 토글이나 별도의 강보정 모드는 추가하지 않는다.
- 피부 세그멘테이션과 얼굴 특징 제외 마스크 구조는 변경하지 않는다.
- 룩 이름을 기반으로 한 임시 필터링은 사용하지 않는다.
