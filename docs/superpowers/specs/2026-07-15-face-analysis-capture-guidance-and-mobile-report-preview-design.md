## 1. 목적

정면 S1 촬영과 ARKit 3D 측정이 연속해서 진행된다는 사실을 촬영 전에 알리고, 사용자가 직접 고칠 수 있는 품질 문제는 촬영 중 한 가지씩 안내한다. 앱은 조건이 안정되면 자동으로 여러 프레임을 수집하고, 실제로 사용할 수 있는 결과가 없을 때만 명확한 이유와 함께 재촬영을 요청한다.

동시에 현재 앱의 얼굴 분석 보고서 구조를 390px 모바일 세로형 HTML로 재현해, 실기기에서 전체 분석을 완료하지 않아도 결과의 정보 구조와 시각 흐름을 검토할 수 있게 한다.

## 2. 확정 원칙

1. 사용자에게는 `두 번 촬영`이 아니라 `카메라를 사용하는 두 단계`로 설명한다.
2. 정면 사진은 셔터 1회, 3D는 셔터 없이 자동 측정한다.
3. 사용자가 고칠 수 있는 촬영 게이트만 촬영 화면에 노출한다.
4. 내부 분석 게이트와 오류 코드는 사용자에게 직접 노출하지 않는다.
5. 실시간 안내는 가장 우선순위가 높은 원인 하나만 보여준다.
6. 조건이 안정되면 자동 수집하고, 일시적인 눈 깜빡임이나 흔들림 때문에 수동 재촬영을 요구하지 않는다.
7. 재촬영은 모든 후보 프레임이 품질 기준을 통과하지 못했을 때만 요청한다.
8. 같은 단계에서 두 번 실패하면 무한 반복하지 않고 안내 재확인 또는 3D 건너뛰기를 제공한다.

## 3. 사용자 흐름

### 3.1 전체 촬영 시작 전

얼굴 분석 시작 화면에서 다음 순서를 미리 보여준다.

```text
카메라는 두 단계로 진행돼요

1. 정면 사진 촬영
   가이드에 맞추면 사진을 한 번 촬영해요.

2. 3D 얼굴 측정
   셔터를 누르지 않고 약 3초 동안 자동으로 측정해요.
```

하단 기본 동작은 `촬영 시작`이다. 보조 문구로 `보통 10초 내외이며, 얼굴을 맞추는 시간에 따라 더 걸릴 수 있어요`를 표시한다. 이 시간은 정렬 시간을 포함한 사용자 기대치이며, 3D의 순수 유효 프레임 수집 시간과 구분한다.

### 3.2 S1 정면 촬영

실시간 게이트의 우선순위는 다음과 같다.

1. 얼굴 없음 또는 여러 얼굴
2. 얼굴 크기와 가이드 위치
3. yaw, pitch, roll 정면 조건
4. 눈 감김, 과한 미소, 입 벌림 등 표정 조건
5. 머리카락·손·마스크 등 가림
6. 노출, 조명 균일도, 초점, 카메라 안정성

각 프레임의 원시 판정을 그대로 보여주지 않는다. 같은 실패가 300ms 이상 지속될 때만 안내를 바꾸고, 모든 조건은 500ms 이상 안정됐을 때 통과 처리한다.

권장 안내 문구:

| 조건 | 사용자 문구 |
| --- | --- |
| 얼굴 없음 | 얼굴을 가이드 안에 맞춰 주세요 |
| 여러 얼굴 | 화면에는 한 명만 나오게 해주세요 |
| 너무 멀거나 가까움 | 얼굴을 조금 더 가까이/멀리 해주세요 |
| 정면 아님 | 고개를 정면으로 맞춰 주세요 |
| 표정 조건 실패 | 입술을 편하게 다물고 표정을 유지해 주세요 |
| 가림 | 얼굴을 가리는 머리카락이나 손을 치워 주세요 |
| 조명 부족 | 얼굴이 고르게 보이도록 밝은 곳으로 이동해 주세요 |
| 카메라 불안정 | 휴대폰을 잠시 고정해 주세요 |

모든 조건이 안정되면 별도의 반복 셔터 없이 짧은 후보 프레임 묶음을 수집하고 가장 품질이 높은 프레임을 S1로 사용한다.

### 3.3 S1 확인 후 3D 진입 전

3D 카메라가 갑자기 시작되지 않도록 전환 안내를 한 번 보여준다.

```text
이제 3D 얼굴 측정이에요

약 3초 동안 정면을 보고
입술을 편하게 다문 채
표정과 고개를 유지해 주세요.

얼굴이 가이드에 맞으면 자동으로 시작해요.
```

기본 동작은 `준비됐어요`다. 사용자가 누르기 전에는 Unity/ARKit 측정을 시작하지 않는다. `나중에 하기`는 제공하지 않으며, 실제 3D 화면의 `건너뛰기`는 유지한다.

### 3.4 3D 측정 중

현재 계약은 유효 프레임 목표 30개, 최소 성공 20개, 유효 프레임 수집 창 최대 3000ms다. 사용자에게 프레임 수보다 시간을 우선 노출한다.

- 정렬 전: `정면을 보고 얼굴 윤곽이 안정될 때까지 유지해 주세요.`
- 수집 시작: `좋아요. 약 3초간 그대로 있어 주세요.`
- 수집 중: 원형 또는 선형 진행률과 `3초 → 2초 → 1초`를 표시한다.
- 완료: 햅틱과 함께 `3D 측정이 완료됐어요.`를 짧게 표시한다.

게이트가 수집 전에 풀리면 정렬 안내로 돌아간다. 수집 도중 잠깐 흔들린 프레임은 버리되, 이미 얻은 유효 프레임은 계약이 허용하는 범위에서 유지한다. 기술 용어와 `0/30` 프레임 카운트는 개발 모드에서만 보조 정보로 표시한다.

## 4. 실패와 재촬영 정책

### 4.1 사용자가 고칠 수 있는 실패

- 정면, 표정, 거리, 가림, 조명, 안정성은 즉시 교정 안내한다.
- 제한 시간까지 통과하지 못하면 가장 오래 지속된 실패 원인 하나와 재시도 버튼을 보여준다.
- 같은 이유로 두 번 실패하면 `안내 다시 보기`와 `3D 측정 건너뛰기`를 함께 제공한다.

### 4.2 사용자가 고칠 수 없는 실패

다음 항목은 촬영 화면에서 숨기고 자동 재시도, 폴백 또는 보고서의 일부 측정 불가로 처리한다.

- 메시 토폴로지 불일치
- Unity/ARKit 내부 준비 실패
- 지표 계산 실패
- AI 단계 실패 또는 낮은 모델 신뢰도
- 서버 분석·저장 실패

사용자 문구는 `3D 측정 일부를 완료하지 못했어요. 정면 사진으로 분석을 계속할게요.`로 통일한다. 내부 오류 코드, 토폴로지 지문, 메시 정점 수는 로그에만 남긴다.

## 5. 모바일 HTML 보고서 미리보기

### 5.1 산출물

- 경로: `docs/previews/face-analysis-report-mobile-preview.html`
- 단일 HTML 파일로 열 수 있어야 한다.
- 외부 서버나 빌드 도구 없이 동작해야 한다.
- 저장소 이미지 자산을 상대 경로로 참조한다.
- 기준 뷰포트는 390px이지만 작은 모바일과 데스크톱 중앙 미리보기에도 대응한다.

### 5.2 시각 논지

따뜻한 아이보리 바탕과 절제된 로즈 포인트를 사용하는 에디토리얼 뷰티 리포트다. 첫 화면은 저장소의 실제 얼굴 이미지를 풀블리드로 사용하고, 이후는 흰 패널보다 여백·타이포그래피·얇은 구분선으로 정보의 위계를 만든다.

### 5.3 콘텐츠 순서

1. 풀블리드 얼굴 이미지와 `PERSONAL BEAUTY REPORT`
2. 얼굴 무드 핵심값: 퍼스널 컬러, 얼굴형, 톤 요약, 추천 무드
3. 분석 핵심 요약
4. S1 얼굴 세로 비율
5. 3D 입체 특성: 30/30 성공 예시와 최대 11개 지표
6. 2D 얼굴 형태 비율
7. 퍼스널 컬러 진단과 조명 보정 상태
8. AI 파이프라인 상태
9. 측정 기반 해석 9항목
10. AI 인상 분석과 맞춤 컨설팅
11. 추천 메이크업 전후 이미지와 적용 포인트
12. 부위별 메이크업 팁
13. 고정 하단 `메이크업 필터 만들기` 동작

예시 수치는 실측값처럼 보이되 화면 구조 검토용 가상 데이터임을 상단에 표시한다. 민감도 3인 비대칭 종합 점수와 황금비 편차는 예시에서도 노출하지 않는다.

### 5.4 상호작용 논지

- 첫 진입 시 표지와 핵심값이 순서대로 나타난다.
- 긴 측정 상세와 11개 3D 지표는 `자세히 보기`로 접고 펼칠 수 있다.
- 추천 메이크업 이미지는 전/후 토글로 비교한다.
- `prefers-reduced-motion`에서는 모든 이동 애니메이션을 제거한다.

## 6. 접근성

- 상태를 색만으로 구분하지 않고 아이콘과 문구를 함께 사용한다.
- 실시간 안내는 같은 문구를 반복 낭독하지 않도록 상태가 안정된 뒤 접근성 라이브 영역을 갱신한다.
- 기본 텍스트 대비는 WCAG AA를 만족시킨다.
- 모든 버튼은 최소 44px 높이를 확보한다.
- 카메라 안내는 한 문장, 한 행동으로 제한한다.

## 7. 검증 기준

### 7.1 촬영 UX

- 시작 전에 S1과 3D의 두 단계가 모두 안내된다.
- 3D 시작 전 `약 3초`와 정면·표정·고개 유지가 안내된다.
- 3D는 사용자 확인 전 시작하지 않는다.
- 실시간 게이트는 동시에 하나의 사용자 행동만 요청한다.
- 성공 이벤트는 `face3d_analyzed`, 유효 프레임 20개 이상, 목표 30개, 필수 5지표 finite 값으로 판정한다.
- 실패 시 `tracking_gate_timeout` 같은 내부 문자열이 사용자에게 노출되지 않는다.

### 7.2 HTML

- 390px에서 가로 스크롤이 없다.
- 현재 앱 보고서의 주요 섹션 순서를 모두 포함한다.
- 저장소 이미지가 깨지지 않는다.
- 접기/펼치기와 전/후 비교가 키보드와 터치로 동작한다.
- 모바일과 1440px 데스크톱에서 시각 검증한다.
