# 메이크업 상황 칩·검수 문구 전환 설계

작성일: 2026-07-15

## 목표

메이크업 추천 첫 화면의 퍼즐 카드맵을 차분하게 훑을 수 있는 칩 목록으로 바꾸고, 상황 문구 생성에는 AI를 사용하지 않는다. 질문 생성과 최종 메이크업 추천 AI 흐름은 그대로 유지한다.

이 문서는 기존 `2026-07-14-makeup-scenario-recommendation-design.md`의 퍼즐 레이아웃 및 AI 상황 문구 생성 결정과 `2026-07-15-makeup-scenario-library-retention-design.md`의 AI 문구 저장 정책을 대체한다. 백엔드 호환 API를 즉시 삭제하는 작업은 포함하지 않지만 모바일 사용자 흐름에서는 더 이상 호출하지 않는다.

## 화면 설계

### 시각 원칙

- 문구 길이에 맞춰 너비가 정해지는 한 줄 칩을 `flexWrap`으로 배치한다.
- 모든 칩은 같은 높이, 같은 글자 크기와 두께를 사용한다.
- 여러 색·폰트 크기·절대 배치를 제거하고 중립적인 반투명 표면과 얇은 경계만 사용한다.
- 문구가 한 줄에 들어가지 않는 좁은 화면이나 큰 글꼴 배율에서는 칩이 가로 폭을 더 차지하되 텍스트를 잘라내지 않는다.
- 최소 44pt 터치 영역과 문구 기반 접근성 레이블을 유지한다.

### 화면 구성

1. 제목과 지난 추천 진입
2. `자주 찾는 메이크업` 고정 칩 5개
3. 직접 작성한 일반 상황 문구 칩 목록
4. 새로고침과 `문구 더보기` 동작
5. 기존 하단 플로팅 자유 입력창과 확인 버튼

상단 5개는 사람들이 자주 찾는 목적을 짧게 표현하고 항상 같은 순서로 고정한다.

1. 데일리로 자연스럽게
2. 출근·등교 단정하게
3. 데이트·약속에서 매력적으로
4. 사진에서 또렷하게
5. 중요한 날 오래 유지되게

고정 칩은 검정에 가까운 채움형 표면으로, 일반 칩은 중립 리퀴드글라스 표면으로 구분한다. 최초 화면은 고정 5개와 무작위 일반 문구 7개로 총 12개를 보여준다. 새로고침은 네트워크 요청 없이 일반 검수 문구 풀을 다시 섞어 일반 7개만 교체하며 고정 5개는 유지한다. 더보기는 같은 세트에서 아직 보이지 않은 일반 문구를 최대 12개씩 추가한다. 전체 문구를 노출한 뒤에는 더보기 버튼을 숨기거나 완료 상태로 비활성화한다.

## 데이터와 상태

- 상황 문구의 단일 원천은 `features/makeup-recommendation/mocks/makeupRecommendation.mock.ts`의 검수된 `MAKEUP_SCENARIOS`다.
- 고정 5개는 같은 파일에서 명시적인 고정 ID 목록과 완전한 `seedPrompt`, `intentTags`, `knownDimensions`를 가진 검수 시나리오로 관리한다.
- `displayText`, `seedPrompt`, `intentTags`, `knownDimensions`는 계속 분리해 화면 카피와 AI 추천 입력의 의미를 보존한다.
- 최초 진입 시 고정 5개를 일반 풀에서 제외하고, 나머지 목록을 임의 seed로 재정렬해 사용자마다 같은 일반 7개만 보이는 문제를 피한다.
- 새로고침은 새 seed로 일반 검수 목록만 재정렬하고 노출 개수를 7개로 되돌린다.
- 더보기는 같은 정렬 목록의 다음 12개를 노출한다. 중복 방지, 로딩, 네트워크 실패 상태는 필요 없다.
- 상황 선택 시 `seedPrompt`와 `intentTags`를 기존 질문 생성 API에 전달한다. 질문 생성, 답변, 최종 추천, 이미지 생성 및 보고서 저장은 변경하지 않는다.

## 컴포넌트 경계

- `ScenarioPuzzleWall`은 `ScenarioChipCloud`로 대체한다.
- `ScenarioPromptCard`의 가변 팔레트와 강조 크기는 칩 전용 단일 스타일로 축소한다.
- `scenarioPuzzleLayout.ts`와 해당 테스트는 사용처가 사라지면 삭제한다.
- `MakeupRecommendationScreen`에서 `fetchGeneratedMakeupScenarios`, 생성 문구 병합·유사도 필터·폴백 로직과 자동 생성 effect를 제거한다.
- 공용 테마와 디자인 시스템은 수정하지 않고 feature 내부 컴포넌트에서 기존 토큰만 사용한다.

## 실패 처리

상황 문구는 로컬 상수이므로 로딩과 네트워크 오류가 없다. 검수 목록이 비어 있는 비정상 상태에서는 빈 화면 대신 자유 입력 흐름을 그대로 사용할 수 있게 한다. 질문 또는 최종 추천 AI 실패 처리는 기존 동작을 유지한다.

## 검증

- 고정 5개가 첫 위치와 고정 순서를 유지하고 채움형 스타일로 구분되는지 확인한다.
- 초기 일반 7개가 고정 5개와 겹치지 않고 검수 목록에서 중복 없이 노출되는지 확인한다.
- 새로고침이 API를 호출하지 않고 일반 문구만 바꾸며 고정 5개를 유지하는지 확인한다.
- 더보기가 다음 문구를 중복 없이 추가하고 끝에서 멈추는지 확인한다.
- 칩 선택이 기존 `scenarioId`, `scenarioLabel`, `seedPrompt`, `intentTags`를 유지하는지 확인한다.
- 402pt 기준 화면과 큰 글꼴 배율에서 문구가 잘리지 않고 최소 터치 높이를 유지하는지 확인한다.
- 모바일 TypeScript 타입체크를 통과한다.

## 제외 범위

- 질문 생성 또는 최종 추천 AI 제거
- 백엔드 시나리오 API·DB 테이블·보존 정책 즉시 삭제
- 공용 테마 변경
- 문구 자체의 전면 재작성
