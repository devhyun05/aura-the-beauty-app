# 수염 레이저 제모 시뮬레이션 — 통합 실행 계획 (조사 → 실험 → 구현 → 테스트)

## Context

기획서 `AURA_BEARD_LASER_REMOVAL_SIMULATION_PLAN_KO.md` v0.1 리뷰 결과 **Yellow**: 기술 방향(결정론 우선, 제한적 인페인팅, geometry guard)은 타당하나 성립 조건인 수염 segmentation 방식이 미정이고, 저장소 현실(빈 shared-contracts, feature-local 계약 관례)과 어긋나는 가정이 있었다. 이 계획은 리뷰 권고를 반영해 **스파이크(게이트) → 결정론 파이프라인 → 가드/튜닝 → 로컬 dev API → RN 화면**까지 전 단계를 실행 순서로 배열한다.

**사용자 결정 사항**
- RN 화면은 **로컬 FastAPI dev 서버**로 랩 엔진과 실제 연결 (온디바이스/백엔드 결정은 이후로 미룸)
- 테스트 사진은 **본인+지인 동의 실사진 10~30장** 직접 준비

**리뷰에서 확정한 스코프 원칙**
- 결정론 경로만으로 첫 검증. **Diffusion inpainting은 defer** (이번 계획에서 제외)
- **sideburn 마스크 미생성**, 설문 7번(피부 자극 — 민감정보) 제거
- 설문은 상담 질문 생성 입력으로만 사용(`shavingState`만 파이프라인에 반영), §3.3 파라미터 보정 매트릭스 제외
- 단계 라벨에 회차 숫자 미노출, AAD/Mayo 인용 앱 내 미노출
- 계약은 feature-local + `scripts/mobile/*.mjs` 가드 관례 (shared-contracts는 빈 패키지 — 사용 안 함)

## Stage 1. 조사/스파이크 — 수염 segmentation 【게이트 ①】

기성 face parsing에는 beard 클래스가 없으므로 3후보 비교 (실사진 10장, 오버레이 그리드 1장 산출):

| 후보 | 구성 |
|---|---|
| C1 | 결정론: 하관 ROI 내 morphological black-hat(+Gabor) → hard hair confidence, 윗볼·이마 참조 패치 Lab GMM Mahalanobis 거리 → shadow confidence |
| C2 | C1 + CLIPSeg(`CIDAS/clipseg-rd64-refined`) "beard" prior 곱 — dense beard 외곽 보강 |
| C3 | face parsing(SegFormer CelebAMask-HQ) — beard가 skin/hair 어디로 가는지 확인용(기각 유력, 확인 비용 낮음) |

판정 기준: ① 입술·콧구멍 침범(protect 교차율) ② dense beard 외곽 커버리지 ③ 어두운 피부 케이스 열화 ④ 장당 처리 시간.

**게이트 결정**: C1/C2 중 채택, 또는 dense beard를 quality gate로 차단하는 제품 결정("수염 짧게 정리 후 촬영 권장"). 실패 시 여기서 중단하고 재기획.

## Stage 3. 파이프라인 골격 (UI 없는 CLI)

`tools/beard-simulation-lab/` — 기획서 §9.2 구조 준용:

```
engine/  detect_face.py, lower_face_roi.py, beard_segmentation.py(스파이크 승자),
         beard_shadow_corrector.py, stubble_inpaint.py, blend.py,
         geometry_guard.py, pipeline.py, contracts.py

```

순서: quality gate → FaceLandmarker → 하관 ROI → 마스크 생성 → **마스크-protect 교차 검사(사전 reject)** → 결정론 보정 → soft 재합성 → geometry guard → 산출.

## Stage 4. 결정론 보정 구현

- **shadow 브랜치**: Lab/LCh 색 보정 + frequency separation(고주파 피부결 보존), blueGraySuppression, 주변 피부 mean matching
- **hair 브랜치**: black-hat 마스크 → OpenCV Telea inpaint (stubble 전용)
- multi-band/feather blending, `preserveDetail` 상시 high
- full-face img2img 금지를 **구조로 강제**: 보정 함수 입력 타입은 lower-face crop+mask만, 출력은 재합성 함수 통과 필수

## Stage 5. Geometry guard + 단위 테스트

- 검사 항목: 마스크-protect 교차(1차 방어), landmark drift(입술·입꼬리·턱끝), jawline IoU, **identity 임베딩 거리(ArcFace류 — 기획서 누락분)**, 마스크 경계 seam score
- pytest 합성 케이스(가드가 진짜 잡는지 검증): 입술 인위 이동 이미지 → reject / protect 침범 마스크 주입 → reject / 타인 얼굴 치환 → identity reject
- 실패 시 완화 시퀀스: 강도↓ → mask erode → margin↑ → 차단 (§8.4)

## Stage 6. Batch 하네스 + 프리셋 튜닝 【게이트 ②】

- batch runner: 30장 × 3단계 → **HTML 그리드 리포트 1장** (튜닝 주력 도구; Gradio는 단일 이미지 디버깅 보조로 후순위)
- 튜닝 순서: **shadow 3단계 먼저 수렴 → hair 강도 얹기** (동시 튜닝 금지)
- metrics.json 자동 지표(§9.7 + identity 거리) + 휴먼 리뷰 시트 3문항: "본인이라 믿기는가" / "**제모된 느낌인가, 면도 직후 느낌인가**" / "피부가 뭉개졌는가"
- **게이트 결정**: 아래 수용 기준 미달 시 RN 단계 진입 보류

## Stage 7. 로컬 dev API

## Stage 8. RN feature

`apps/mobile/src/features/beard-simulation/` — 기존 feature 관례(face-ratio 참조: `types.ts`, `constants.ts`, `screens/`, `components/`, `services/`+colocated test):

## 수용 기준 (게이트 ②)

1. 실사진 30장: 사전 reject 제외 guard 통과율 ≥90%
2. identity 임베딩 거리 임계 이하 100%
3. 블라인드 휴먼 리뷰 "본인 맞음" ≥95%, "제모/감소된 느낌" 과반
4. 어두운 피부톤 서브셋에서 유의한 품질 저하 없음
5. 합성 케이스 pytest 전부 통과 (가드가 실제로 잡음을 증명)

## 검증 방법

- Stage 1: 10장×3후보 오버레이 그리드를 사람이 판정 (판정 기준 4개 체크리스트)
- Stage 3~5: `python cli.py samples/x.jpg --stage medium` → run 디렉토리 산출물 육안 확인 + pytest
- Stage 6: batch HTML 리포트 + metrics.json
- Stage 8~9: 시뮬레이터에서 실 사진으로 전체 플로 구동, 실패 케이스(가림 사진) 투입해 실패 UX 확인

## 주요 리스크와 대응

- segmentation 실패 → **게이트 ①에서 중단** (뒤 단계 매몰 비용 없음)
- dense beard 미해결 → quality gate 차단으로 제품 범위 축소 (defer된 diffusion은 그 후 재검토)
- 어두운 피부 편향 → 본인 피부 참조(GMM) 설계 + 전용 테스트 서브셋으로 상시 측정
- 실사진 유출 → gitignore + 로컬 전용 + reports에는 지표만
