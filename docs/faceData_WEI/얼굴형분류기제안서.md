# 얼굴형 분류기 iPhone 이식 제안서 v0.1

## 0. 목적

AURA의 얼굴 촬영/분석 플로우에 **사진 1장 기반 얼굴형 분류기**를 iPhone에서 실행 가능한 형태로 이식한다.

목표 얼굴형 taxonomy는 다음 7종이다.

```text
oval
round
square
heart
oblong
diamond
triangle
```

단, 최종 UX는 얼굴형을 단정적으로 하나만 말하는 것이 아니라, 다음처럼 **확률/점수 기반 결과**를 제공한다.

```text
dominantShape: oval
top2: oval 0.68, round 0.21
confidenceGap: 0.47
faceShapeScores:
  oval: 0.68
  round: 0.21
  square: 0.14
  heart: 0.08
  oblong: 0.18
  diamond: 0.12
  triangle: 0.05
```

AURA 내부 기준서도 얼굴형을 단일 hard label로 저장하기보다 `faceShapeScores`, dominant traits, confidence로 저장하는 방향을 지향한다.

---

## 1. 핵심 결론

Rob4343/FaceShapeAI는 **로컬 서버 실험용 baseline**으로는 좋지만, iPhone 앱에 직접 넣기 좋은 구조는 아니다.

이식 전략은 다음 순서가 가장 현실적이다.

```text
Phase 1. Rob4343/FaceShapeAI로 빠른 로컬 서버 baseline 검증
Phase 2. iPhone 내부 MediaPipe FaceLandmarker + rule classifier 구현
Phase 3. chetx27 / rajendra / hirunaofficial 룰을 AURA식 feature로 통합
Phase 4. 한국인/동아시아 테스트셋으로 threshold 보정
Phase 5. 데이터가 쌓이면 Core ML 모델로 대체 또는 보조
```

최종 권장 구조:

```text
iOS Native Camera
→ 사진 1장 촬영
→ 품질 gate
→ MediaPipe FaceLandmarker 478 landmarks
→ FaceShapeFeatureExtractor
→ Rule-based 7-class scorer
→ faceShapeScores / top2 / confidenceGap
→ 분석 리포트 저장
```

AURA는 이미 iOS Native MediaPipe FaceLandmarker 경로를 갖고 있으므로, 완전히 새로운 얼굴 분석 라이브러리를 붙이기보다 **기존 MediaPipe 경로 위에 얼굴형 feature extractor와 rule scorer를 추가**하는 것이 가장 작고 안전하다. 현재 AR Makeup Engine 컨텍스트에서도 iOS native `E7NativeFaceRegionProviders.swift`가 MediaPipe FaceLandmarker 478 mesh를 사용하고, normalized landmarks와 faceProfile metrics를 생성하는 구조가 정리되어 있다.

## 3. Rob4343/FaceShapeAI 평가

### 3.1 장점

Rob4343/FaceShapeAI는 사진 1장을 넣어 얼굴형을 예측하는 baseline으로 유용하다.

장점:

```text
- 이미 학습된 모델 형태가 있음
- 사진 1장 입력 실험에 적합
- 빠르게 로컬 서버로 붙여 결과를 볼 수 있음
- probability/confidence 형태 결과를 얻기 좋음
```

### 3.2 한계

iPhone 직접 탑재에는 적합하지 않다.

이유:

```text
- Python 기반 구조
- scikit-learn joblib/pickle 모델 사용
- iOS에서 joblib.load(), predict_proba()를 그대로 실행할 수 없음
- 전처리 코드까지 Swift/TypeScript로 옮겨야 함
- 모델 포맷이 .mlmodel, .tflite, .onnx가 아님
```

따라서 Rob4343/FaceShapeAI는 다음 위치에 둔다.

```text
사용한다:
- 로컬 서버 baseline
- 모델 결과 비교 기준
- top1/top2 confidence UX 참고
- 7-class 또는 5-class 분류 성능 감 잡기

사용하지 않는다:
- iPhone 앱 내부 직접 탑재
- 최종 production classifier
```

## 4. Core ML 평가

### 4.1 정확한 의미

Core ML은 얼굴형을 자동으로 분류해주는 라이브러리가 아니다.

```text
Core ML = iPhone에서 ML 모델을 실행하는 런타임/포맷
얼굴형 분류기 = 우리가 직접 만들거나 학습해야 하는 모델
```

즉, Core ML은 “분류기”가 아니라 **나중에 우리가 만든 분류기를 iPhone 안에서 실행하기 위한 그릇**이다.

### 4.2 언제 쓰나

Core ML은 MVP 시작점이 아니라, 데이터가 쌓인 뒤 사용한다.

```text
Rule classifier로 테스트
→ 사람 라벨과 비교
→ feature vector 저장
→ 200~500장 이상 데이터 확보
→ 작은 classifier 학습
→ Core ML 변환
→ iPhone on-device inference
```

### 4.3 Core ML 후보 모델 형태

얼굴형 분류에는 두 가지 Core ML 모델 전략이 가능하다.

#### A. Feature-vector classifier

입력:

```text
faceLengthToCheekWidth
foreheadToCheek
jawToCheek
chinToCheek
templeToCheek
cheekDominance
jawAngleScore
contourRoundness
```

모델:

```text
Logistic Regression
Decision Tree
Random Forest
Gradient Boosting
Small MLP
```

장점:

```text
- 가볍다
- 설명 가능하다
- rule classifier에서 자연스럽게 확장 가능하다
- iPhone 실행 비용이 낮다
```

#### B. Image classifier

입력:

```text
정렬된 얼굴 crop 이미지
```

모델:

```text
MobileNet
EfficientNet-Lite
Vision Transformer tiny
```

장점:

```text
- landmark rule로 잡기 어려운 윤곽 패턴을 학습할 수 있다
```

단점:

```text
- 데이터 품질이 전부다
- 왜 그렇게 분류했는지 설명하기 어렵다
- 한국인/동아시아 얼굴에서 oval/round 오분류 가능성이 높다
```

초기에는 **A. feature-vector classifier**가 더 적합하다.

## 5. 참고 프로젝트 1: chetx27/cvproject-facefilter

### 5.1 참고 가치

chetx27 프로젝트는 MediaPipe 기반 7-class 얼굴형 rule baseline으로 가장 직접적인 참고 가치가 있다.

지원 taxonomy:

```text
Oval
Round
Square
Heart
Diamond
Oblong
Triangle
```

주요 feature:

```text
face_ratio = face_length / cheek_width
jaw_ratio = jaw_width / cheek_width
forehead_ratio = forehead_width / cheek_width
temple_ratio = temple_width / cheek_width
```

### 5.2 가져올 것

```text
- 7-class 분류 구조
- 얼굴 길이/광대폭/턱폭/이마폭/관자폭 비율
- threshold 기반 seed rule
- MediaPipe landmark index 활용 방식
```

### 5.3 그대로 쓰면 안 되는 것

```text
- threshold를 그대로 production에 적용
- top1 hard label만 출력
- 실시간 50-sample majority vote 구조를 사진 1장에 그대로 적용
```

AURA에서는 다음처럼 변환한다.

```text
chetx hard rule
→ 각 얼굴형 score 계산
→ top1/top2 산출
→ confidenceGap 계산
→ low confidence면 혼합형 표현
```

## 6. 참고 프로젝트 2: rajendra7406/FaceShape

### 6.1 참고 가치

rajendra7406/FaceShape는 OpenCV + Dlib 기반이지만, 얼굴형 rule 설계 아이디어가 단순해서 iPhone 포팅 관점에서 참고할 만하다.

주요 feature:

```text
forehead length
face width
jawline length
face length
jaw angle
```

지원 taxonomy는 다음과 유사하다.

```text
oval
rectangular
oblong
square
round
diamond
triangle
```

### 6.2 가져올 것

```text
- jawline length 개념
- jaw angle 계산
- face length / face width 기반 분기
- rectangular / oblong / square의 구분 아이디어
```

### 6.3 AURA식 변환

Dlib 68 landmarks를 그대로 쓰지 않고 MediaPipe 478 landmarks로 치환한다.

```text
Dlib jawline
→ MediaPipe face oval 하관 segment

Dlib forehead width
→ MediaPipe + hair/skin segmentation 또는 추정 confidence 낮음 처리

Dlib jaw angle
→ 좌우 jaw 기준점 + 턱끝 Me 기준 각도

rectangular
→ oblong 또는 square-oblong hybrid score로 매핑
```

## 9. Feature Extractor 설계

### 9.1 입력

```ts
type FaceShapeFeatureInput = {
  imageWidth: number;
  imageHeight: number;

  landmarks: Array<{
    x: number;
    y: number;
    z?: number;
    visibility?: number;
  }>;

  quality: {
    yaw?: number;
    pitch?: number;
    roll?: number;
    blurScore?: number;
    lightingScore?: number;
    expressionNeutralScore?: number;
  };
};
```

### 9.2 출력 feature

```ts
type FaceShapeRuleFeatures = {
  faceLengthToCheekWidth: number;

  foreheadToCheek?: number;
  jawToCheek: number;
  chinToCheek: number;
  templeToCheek?: number;

  cheekDominance: number;
  jawWidthScore: number;
  jawAngleScore: number;
  chinPointedness: number;
  contourRoundness: number;
  foreheadDominance?: number;

  quality: {
    frontalScore: number;
    landmarkConfidence: number;
    hairlineConfidence?: number;
  };
};
```

### 9.3 기준점

AURA 기준서의 핵심 기준점을 사용한다.

```text
H  = Hairline Center
G  = Glabella/Brow Line
Sn = Subnasale
Me = Menton/Chin
FW = Face Width
FHW = Forehead Width
CW = Cheekbone Width
JW = Jaw Width
CHW = Chin Width
IPD = Interpupillary Distance
```

주의:

```text
- 헤어라인이 가려지면 H/FHW 기반 feature는 low confidence 또는 null
- 코끝은 세로 3분할 기준점으로 쓰지 않음
- 정면 품질이 낮으면 얼굴형 결과를 blocked 또는 low confidence 처리
```

## 10. Rule Scorer 설계

### 10.1 기본 방향

얼굴형을 if/else로 하나만 반환하지 않는다. 각 얼굴형에 대해 score를 계산한다.

```ts
type FaceShapeLabel =
  | 'oval'
  | 'round'
  | 'square'
  | 'heart'
  | 'oblong'
  | 'diamond'
  | 'triangle';
```

### 10.2 score 계산 예시

```text
oblong score:
- faceLengthToCheekWidth 높음
- jawToCheek 중간
- contourRoundness 중간

round score:
- faceLengthToCheekWidth 낮음
- contourRoundness 높음
- jawAngleScore 낮음

square score:
- jawToCheek 높음
- jawAngleScore 높음
- chinToCheek 높음

heart score:
- foreheadToCheek 높음
- jawToCheek 낮음
- chinPointedness 높음

diamond score:
- cheekDominance 높음
- foreheadToCheek 낮음
- jawToCheek 낮음

triangle score:
- jawToCheek 높음
- foreheadToCheek 낮음
- lowerFaceWeight 높음

oval score:
- 극단 trait 적음
- faceLengthToCheekWidth 중간~약간 높음
- jawAngleScore 낮음~중간
- contourRoundness 중간 이상
```

### 10.3 confidence 계산

```ts
confidenceGap = top1.score - top2.score;
```

권장 UX 기준:

```text
confidenceGap >= 0.20
→ dominantShape 단정 표현 가능

0.10 <= confidenceGap < 0.20
→ “Oval에 조금 더 가까워요” 표현

confidenceGap < 0.10
→ “Oval과 Round 특징이 함께 보여요” 표현
```

## 11. 품질 Gate

사진 1장 기반 얼굴형 분류는 pose와 crop에 민감하다. 따라서 촬영 품질 gate가 필수다.

초기 기준:

```text
- |yaw| <= 8도
- |pitch| <= 8도
- |roll| <= 5도
- blurScore 기준 통과
- lightingScore 기준 통과
- 과한 표정 제외
- 얼굴 전체 윤곽이 프레임 안에 들어옴
- 앞머리/모자/마스크/손 가림 warning 처리
```

AURA 기준서도 단일 사진은 눈 깜빡임, 표정, 흔들림, 조명, 고개 각도에 취약하므로 안정 프레임 집계를 기본값으로 권장한다.

MVP는 사진 1장을 목표로 하되, 가능하면 촬영 직전 0.5~1초 동안 안정 프레임을 보고 가장 좋은 프레임을 선택한다.

## 13. 구현 단계

### Phase 0. Rob4343 로컬 서버 baseline

목표:

```text
- 기존 Rob4343/FaceShapeAI 결과를 빠르게 확인
- sample image 20~50장으로 결과 경향 파악
- top1/top2/confidence UX 참고
```

결과물:

```text
- local FastAPI 또는 Flask endpoint
- sample image 결과 로그
- 사람 라벨과 비교한 간단한 표
```

이 단계는 iPhone 이식 전 성능 감을 잡기 위한 실험이다.

---

### Phase 1. iPhone rule classifier MVP

목표:

```text
- iPhone 안에서 서버 없이 얼굴형 결과 생성
- MediaPipe 478 landmarks 재사용

```

작업:

```text
1. FaceShapeFeatureExtractor 구현
2. FaceShapeRuleScorer 구현

```

수용 기준:

```text
- 사진 1장 입력으로 result 반환
- no face에서 blocked 반환
- top1/top2/faceShapeScores 반환
- debugFeatures 반환
- 앱 전체 분석 flow가 깨지지 않음
```

---

목표:

```text
templeToCheek
cheekDominance
jawAngleScore
chinPointedness
contourRoundness
```

### Phase 4. Ensemble

목표:

```text
- rule과 Core ML을 함께 사용
- ML이 틀리는 경우 rule explanation으로 보완
```

구조:

```text
rule scores
+ coreml probabilities
+ quality confidence
→ final faceShapeScores
```

예시:

```text
finalScore = 0.6 * coremlProbability + 0.4 * ruleScore
```

단, Core ML 모델 품질이 충분히 검증되기 전에는 rule을 primary로 둔다.

## 15. 개발자가 주의할 점

### 15.1 hard label 단정 금지

금지:

```text
당신은 사각형 얼굴입니다.
```

권장:

```text
하관 폭과 턱선 각도감이 비교적 높아
Square 계열 특징이 일부 감지됐어요.
```

### 15.2 헤어라인 추정 금지

앞머리나 모자로 헤어라인이 가려진 경우:

```text
foreheadToCheek = null
hairlineConfidence = low
warnings += ['hairline_covered']
```

### 15.3 사진 1장 결과를 과신하지 않기

사진 1장 분류는 다음에 취약하다.

```text
- 고개 각도
- 카메라 거리
- 렌즈 왜곡
- 표정
- 앞머리
- 조명
- crop
```

따라서 항상 quality와 warnings를 함께 저장한다.

### 15.4 landmark index hardcoding은 문서화

MediaPipe landmark index를 직접 쓰는 경우 반드시 문서화한다.

```text
- cheek left/right 기준점
- jaw left/right 기준점
- chin 기준점
- brow/forehead 보조 기준점
- temple 기준점
```
