## 1. 왜 정밀 모드가 필요한가 (실측으로 확인된 문제)

기본 측정은 "조명 × 피부색"이 곱해진 값을 본다. 실기기 확인:

- 같은 사람이 **창가=봄 라이트, 자리=봄 웜(트루)** 로 세부 타입이 흔들림 (시즌은 유지).
- 카메라 AWB-lock 이후에도 잔여 캐스트가 축(특히 웜/쿨·채도)을 0.2~0.8 이동시킴 (합성 스윕).

## 2. 시도한 무료 보정 2종과 결과 (2026-07-07 A/B)

### 2-1. 흰자(sclera) 기준 캐스트 정규화 — ✅ 메커니즘 검증, ⚠️ 구조적 한계 확인

**원리**: 흰자는 "원래 색을 아는" 프레임 내 기준물. 흰자의 채널 불균형 = 조명 캐스트로 보고
von Kries 역게인을 얼굴 전 부위에 적용.

**검증된 것**:
- 합성 캐스트 스윕 15/15 복원 (오차 0.2~0.8 → 0.005~0.025), 캐스트로 뒤집힌 시즌 전부 원복.
- 실기기: 서로 다른 조명(창가/자리)에서 보정 후 **같은 타입으로 수렴** — 조명 간 일관성 확보.

**실측으로 확인된 함정들** (전부 게이트로 대응 완료):

| 함정 | 증상 | 대응 (구현됨) |
|---|---|---|
| 눈물언덕·눈꺼풀 피부(분홍) 오염 | 전역 red-cut → 전원 웜+뮤트(가을 뮤트)로 수렴 | 눈 코너 좌우 20% trim |
| 아래 눈꺼풀 waterline(밝고 글로시한 분홍) | 밝기 코호트를 통과해 red 오염 | bbox 하단 18% trim |
| 눈 감김/블링크 | 눈꺼풀 피부가 흰자로 샘플됨 | 픽셀 종횡비 <0.2 스킵 |
| 홍채/그늘/글린트 | 저채도라 절대 게이트 통과 | 상위 밝기 코호트(p90×0.75) + 상대 채도(28%) |
| 사이드광 | 좌우 눈이 다른 캐스트 보고 | 좌우 log-게인 불일치 >0.1 → 보정 포기 |
| **충혈 (핵심 발견)** | a*만 상승, b*는 정상 → 캐스트로 오인하면 얼굴 오염 | 충혈 감지기(아래) |

**★ 핵심 실측 데이터 (재보정 기준)**:
- 실측 흰자(주광 창가, n=1, 밤샘 충혈 상태): **a* 6.7~7.0 / b* 5.9~6.2**
- **b*는 기준(+6.0)에 명중** → "흰자는 약간 노랗다(황색조)" 가정 검증됨.
- **a*는 충혈로 부풀려짐** → 기준 a*는 +4.0으로 부분 반영 (비충혈 추정). 표본 늘려 재적합 필요.
- 현재 기준 흰자: `scleraReferenceRgb = {200,185,177}` ≈ **Lab(76, +4, +6)**.

**★ 충혈 감지기 (조명 vs 충혈 판별식)**:
- 조명 캐스트는 a*·b*를 **함께** 움직인다 (웜광 = 빨강+노랑).
- 충혈은 **a*만** 끌어올린다.
- 판별: `Δa* − 0.5·max(0, Δb*) > 2.5` → 충혈 의심 → 보정 포기 (`sclera_redness_suspected`).

**구조적 한계 (게이트로 못 없앰)**: 흰자 방식은 **눈 상태(충혈·피로)에 민감 = 같은 사람도
날마다 변동 가능**. 충혈 시 보정 불가가 정직한 최선. → 정밀 모드에서 화면 플래시가 필요한 근거.

### 2-2. WB gains 잔여 보정 — ❌ 가설 기각 (기기 캘리브레이션 없이는 무효)

**원리**: 촬영 메타데이터 `whiteBalanceGains`(카메라가 적용한 채널 증폭)로 조명을 역추적,
AWB under-correction 잔여분을 부분 보정.

**기각 근거**:
- 합성 스윕: 개선 0 (0.733→0.740, 오히려 미세 악화).
- 적대 검증: 멀쩡한 이미지에 0.25~0.42 축 오차 주입 가능 확정.
- 근본 원인: **"중립광일 때 게인"이 기기·센서마다 다른데 기준점이 없음**. 얼굴 지배 프레임에선
  AWB 자체가 피부색을 캐스트로 오인하기도 함.

**현 상태**: `wbApplyEnabled=false` — 적용은 꺼짐, **추정치는 매 촬영 로그로 수집 중**.

**부활 경로 (정밀 모드에서)**: 흰자 보정이 성공한 촬영들의 (WB 게인 ↔ 흰자 추정 캐스트) 쌍이
로그에 쌓이고 있음 → 이 쌍으로 **기기별 중립 게인을 역산(캘리브레이션)** 하면 WB 보정을
기준점 있는 상태로 되살릴 수 있다. WB가 가치 있는 곳 = 흰자가 죽는 곳(어두움·사이드광·충혈)
이므로 폴백으로서 상보적.

## 3. 방법론 인사이트 (일반 원칙으로 보존)

1. **일관된 수렴 ≠ 정답.** 상수 편향도 일관된 결과를 만든다(전원 "가을 뮤트" 사례).
   반드시 실측 중간값(실측 흰자 Lab)을 노출해 편향을 분리 진단할 것.
2. **fail-safe 원칙**: 판별 불가면 보정하지 말 것 (좌우 불일치·충혈·클리핑·표본 부족 전부 포기).
   "미적용 + 사유 표시"가 오답보다 낫다.
3. **A/B 병기 구조**: baseline 불변 + 보정판 병기 → 기각(WB)도 피해 없이 빠르게 확정 가능했음.
4. **부분집합 비교 금지**: 보정이 일부 캡처에만 적용되면 "보정 어려운 캡처가 걸러진" 유리한
   비교가 됨 → 전 캡처 적용 시에만 재현성 비교.
5. **진단 데이터를 UI에**: 스크린샷만으로 원격 디버깅 가능하게 (실측 흰자 a*/b*, 미적용 사유).
   이 세션의 충혈 규명이 정확히 이 경로로 이뤄짐.

## 4. 정밀 모드 (추가 서비스) 설계 방향 — 사용자 확정 사항

> 2026-07-07 사용자 결정: 정밀 측정은 **나중에 별도 추가 서비스로 분리**한다.
> 그때 흰자·WB를 아래처럼 활용한다.

### 4-1. 화면 플래시 (screen-flash colorimetry) — 주 측정
- 어두운/약한 조명 환경으로 안내 → 촬영 순간 화면 전체를 최대 밝기 백색으로
  (아이폰 Retina Flash 방식) → **지배 광원 = 폰 화면 = 분광 특성을 우리가 앎** → 조명 미지수 제거.
- 확장: R/G/B 순차 점등으로 반사율 자체 추정 가능.
- 눈 상태에 **의존하지 않음** → 흰자 방식의 구조적 한계(충혈) 회피.
- `calibrationApplied`/definitive 승격 조건과 결합: 화면 플래시 촬영 = definitive 후보.

### 4-2. 흰자 보정 — 보조 검증 + 게이트 (사용자 확정: "잘 이용")
- 화면 플래시 측정의 **교차 검증**: 플래시 광원 하 흰자가 기준색과 일치하는지로 측정 유효성 확인.
- **보정 미적용이면 재촬영 유도**: 현재는 미적용 시 그냥 기존 결과만 보여주지만, 정밀 모드에선
  사유별 안내와 함께 재촬영 플로우로 연결한다 —
  `too_few_samples` → "더 밝은 곳에서" / `left_right_disagree` → "빛을 정면으로" /
  `redness_suspected` → "눈이 충혈된 상태예요. 휴식 후 다시" (측정 자체를 보류).
- 기준 흰자(Lab 76/+4/+6)는 수집 로그로 재적합 후 사용.

### 4-3. WB 게인 — 기기 캘리브레이션 후 폴백 (사용자 확정: "활용")
- 로그에 쌓인 (WB 게인 ↔ 흰자 캐스트) 쌍으로 기기별 중립 게인 캘리브레이션.
- 캘리브레이션 완료 기기에서만 `wbApplyEnabled` 활성화, 흰자 불가 조건의 폴백으로.

### 4-4. 제품 프레이밍
- 무료: 현행 상대 측정 + 정직한 헤지(provisional) — 지금 그대로.
- 정밀 모드(유료/추가): 화면 플래시 프로토콜 + 흰자 교차검증 + 재촬영 가이드 + definitive 판정.
- 프라이버시 불변식 동일(온디바이스 전용, 업로드 없음).
