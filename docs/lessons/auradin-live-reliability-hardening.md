# 라이브 신뢰성 1차 실패 3원인 — 질의 스팸 오염 · '블러셔' 파서 실버그 · 발색 라벨 확률 리젝

WS5 1차 측정(live 성공 20%, bedrock 카피 96.7%)의 원인과 수정. 재측정 2회 연속 전항목 PASS.

1. **긴 발견 질의는 Naver top-sim을 리셀러 스팸으로 오염시킨다.** "립 틴트 립스틱 플럼"류
   토큰 스택 질의의 상위 결과는 brand/maker 공란(롯데ON 등) → `brand_not_whitelisted`로 전멸.
   수정: `_discovery_queries` 사다리(라벨 질의 → 카테고리 축 → 폴백 축), display 30.
   조건 완화 아님 — 하드 필터는 결과 아이템에 그대로 적용(§9).
2. **`intent_parser`의 velvet 단서 '블러'가 '블러셔/블러쉬' 안에서 오탐.** 모든 치크 질의에
   finish=velvet 소프트 선호가 자동 주입돼 랭킹·발견 질의를 오염시켰다. 수정:
   `_finish_safe_text`가 finish 매칭 전 '블러[셔쉬시]'를 마스킹. 회귀 테스트 고정.
3. **카피 충실성 리젝은 확률적.** temperature 0.3에서도 Claude가 "선명한 발색" 같은
   `ATTRIBUTE_LABELS` intensity 라벨을 무근거로 섞는다(런당 ~1건). 게이트가 §9대로 잘 막은 것 —
   수정은 게이트 완화가 아니라 (a) 프롬프트에 발색·색·마감 라벨 사용 조건 명시, (b) 리젝 시 1회 재시도.

교훈: 신뢰성 지표가 낮으면 게이트를 의심하기 전에 **입력(질의·파서)과 생성(프롬프트)** 쪽을 먼저 진단한다.
진단은 리젝 사유 히스토그램(per-query reject Counter)이 가장 빨랐다.
