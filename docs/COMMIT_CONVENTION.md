# 커밋 메시지 컨벤션

본 프로젝트에서는 커밋 메시지의 일관성을 유지하기 위해 Conventional Commits 스타일을 기반으로 커밋 컨벤션을 정의한다. 커밋 메시지는 작업 내용을 한눈에 파악할 수 있도록 `type: message` 형식으로 작성한다.

## 커밋 메시지 형식

```text
type: commit message
```

예시:

```text
feat: 게시글 작성 기능 구현
fix: 로그인 토큰 만료 오류 수정
docs: README 프로젝트 개요 작성
```

## 현재 허용 커밋 타입

현재 `commitlint.config.js` 기준으로 허용되는 타입은 아래와 같다.

| 타입 | 설명 | 예시 |
| --- | --- | --- |
| feat | 새로운 기능 추가 | `feat: 게시글 작성 기능 구현` |
| fix | 버그 수정 | `fix: 로그인 실패 시 에러 메시지 출력 오류 수정` |
| docs | 문서 작성 또는 수정 | `docs: README 기술 스택 설명 추가` |
| refactor | 기능 변경 없이 코드 구조 개선 | `refactor: 게시글 서비스 로직 분리` |
| test | 테스트 코드 추가 또는 수정 | `test: 로그인 API 테스트 코드 추가` |
| chore | 빌드 설정, 패키지 설정, 환경 설정 등 기타 작업 | `chore: 프로젝트 초기 설정 파일 추가` |
| ci | CI/CD 설정 수정 | `ci: GitHub Actions 배포 워크플로우 추가` |

## 작성 규칙

| 규칙 | 설명 |
| --- | --- |
| 타입은 소문자로 작성 | `Feat`, `FIX`가 아닌 `feat`, `fix`처럼 작성한다. |
| 메시지는 한글로 작성 | 프로젝트 이해도를 높이기 위해 커밋 메시지는 한글로 작성한다. |
| 한 커밋에는 하나의 작업만 포함 | 기능 추가와 버그 수정이 섞이면 커밋을 분리한다. |
| 메시지는 간결하게 작성 | 변경 내용을 짧고 명확하게 작성한다. |
| 기능 변경이 없는 작업은 구분 | 문서 수정은 `docs`, 설정 변경은 `chore`, 코드 구조 변경은 `refactor`를 사용한다. |

## 커밋 예시

```text
chore: 프로젝트 초기 환경 설정
feat: 회원가입 API 구현
feat: 게시글 목록 조회 기능 구현
fix: 댓글 작성 시 새로고침되는 문제 수정
docs: README 프로젝트 개요 추가
refactor: 인증 로직 서비스 계층으로 분리
test: 로그인 API 테스트 코드 추가
ci: GitHub Actions 배포 워크플로우 추가
```

## 확장 타입 후보

아래 타입은 Conventional Commits에서 자주 쓰이거나 도메인별로 사용할 수 있는 확장 타입이다. 현재 commitlint 설정에는 포함되어 있지 않으므로, 사용하려면 먼저 `commitlint.config.js`의 `type-enum`에 추가해야 한다.

| 타입 | 설명 | 예시 |
| --- | --- | --- |
| style | 코드 포맷팅, 들여쓰기, 세미콜론 등 기능 변경 없는 수정 | `style: 게시글 목록 컴포넌트 코드 정렬` |
| build | 빌드 관련 설정 수정 | `build: Dockerfile 설정 추가` |
| perf | 성능 개선 | `perf: 게시글 검색 쿼리 최적화` |
| revert | 이전 커밋 되돌리기 | `revert: 게시글 삭제 기능 롤백` |
| db | 데이터베이스 관련 작업 | `db: 게시글 태그 매핑 테이블 추가` |
| rag | RAG 관련 기능 작업 | `rag: 유사 게시글 추천 기능 구현` |
| mcp | MCP 도구 또는 연동 작업 | `mcp: 외부 뉴스 API 연동 도구 추가` |
| agent | Agent 기능 작업 | `agent: 게시글 작성 보조 Agent 기능 구현` |
