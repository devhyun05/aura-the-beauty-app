## 1. 무엇이 왜 깨져 보였나 (수정 완료)

### 1-1. "아이라이너 윙이 지그재그로 깨짐" → 사실 아이섀도였음
- **증상**: 롱 캣아이 포인트 룩에서 눈꼬리에 검은 번개 모양 플랩.
- **원인**: §16b 와이드 마스크(`ext_wing_sweep`, 2:1)가 아이섀도 밴드의 "꼬리 수평 스윕"(상단을 ≈170°로 눕히는 지오메트리)과 충돌 — 연장·코너 컬럼 상단이 한 점에 역순으로 겹쳐 마스크 윙이 4~5겹으로 그려짐.
- **수정**: 와이드 마스크 활성 시 스윕 비활성(`IrisRenderer._eyeshadowMaskWide`). 파라메트릭 12종은 스윕 유지.
- **교훈**: 증상 부위(라이너)와 원인 부위(섀도)가 달랐음. 브리지 페이로드는 iOS 로그에서 `<private>`로 가려지므로, RN 컴파일을 jest 프로브로 직접 실행해 실제 전송값을 확인하는 방법이 유효했음(메모리에 기록됨).

### 1-2. 아이라이너 밴드 자체의 접힘·왜곡 3종 (EyelinerStyleRenderer)
| 증상 | 원인 | 수정 |
|---|---|---|
| 윙 접힘 | 점별 법선 오프셋 폭 > 코너 곡률 반경 | 현(chord) 법선 평행 오프셋 |
| 곡선 역행 | 균등 매개변수 Catmull-Rom이 눈꼬리 조밀 랜드마크에서 오버슈트 | centripetal(α=0.5) 스플라인 |
| 세로 "깃대+깃발" | UV가 컬럼 인덱스 균등(눈꼬리 6배 압축) | 호길이 균등 리샘플 |
| 라인이 눈에 안 붙음 | 텍스처 라인 코어가 밴드 하단 10% 위 | 밴드 6% 하강(BaselineSink) |
| V자 접합·뭉툭한 끝 | 생성기 윙 상승 램프 기울기 불연속·늦은 테이퍼 | C1 이즈인 + 조기 테이퍼 |
- 윙 지오메트리 꺾임(`WingRise`) 자체를 제거 — **윙 모양은 전적으로 마스크 텍스처가 결정**(캔버스는 접선 직선 연장).
- 스타일 튜닝: `liner_cat_long` rise 0.42, 두께 0.07/0.17, 윙 캔버스 `WingLenFactor` 0.42.

### 1-3. 언더섀도 "사각 블롭" 3계열
- **마스크 미라우팅**: 하부 마스크는 profile 6일 때만 쓰이는데 룩 잎에 shape 지정이 없으면 profile 0(사각 밴드)으로 떨어짐 → `model.ts`가 `eyeshadowLowerMaskImported=1`이면 **profile 6 자동 라우팅**.
- **role 'base' 겸용(surface=2)**: 글리터 팝 등 base 섀도가 하부 밴드에도 profile 0으로 칠해짐 → **profile 0 수식 자체를 개선**(LowerLid.shader: 좌우 페더 ~25%, lash 밀착 스머지). 데일리 베이지·코랄 그늘·로지 언더·모브 시머도 동시 해결.
- **마스크 좌우 페더 협소**(글램 스모키 "앞뒤 뚝 끊김"): 생성기 언더 마스크 7종 페더 ≥20%로 확장.
- 스모키 프리셋: `eyeshadowLowerShape: 2` 추가(정본 실루엣 마스크 사용) + 강도 0.18.

### 1-4. 아래 라이너 텍스처 구분 안 됨
- 펜슬/스머지 파우더가 리퀴드와 차이 없음 → 시드 페더 대폭 확대(펜슬 edge 0.45+grain 0.6, 스머지 edge 0.9), **'리퀴드' 칩 신설(enum 3, 무변조)**, 기본값 리퀴드.
- 시드는 `regions.ts TEXTURE_ENUM_SEED` ↔ `Finish.cginc TEX_SEED(11,·)` **정확 미러** — 한쪽만 고치면 안 됨.

## 2. 신규 기능: 눈꼬리 연장 (짧은 눈·꼬막눈 테크닉)

**콘셉트**: 아래 라이너를 눈 라인 그대로가 아니라, 꼬리 구간에서 **삼각존 하단 경계를 따라 서서히 내려 그리고(트레이스=디태치)**, 눈꼬리 밖까지 **거의 1자로 연장**. 위 라이너 윙과의 사이에 생기는 삼각존 쐐기는 삼각존 음영이 채움.

- **하부 밴드 연장 캔버스**: `LowerLidRenderer`에 눈꼬리 밖 연장 컬럼 4개(눈폭 22%), `uv.x(along)>1` 관례로 셰이더가 식별. 연장 방향은 눈 장축(수평) — 코너 접선은 상승해서 라인 끝이 들림. 코너 진입 4컬럼은 법선을 현 법선으로 블렌드(경계 접힘 방지).
- **부위별 게이트**: 컨실러·애교살은 눈 구간에서 정지, 언더섀도는 마스크 우측 엣지 클램프 연장×페이드(상부 §16 관례), 라이너는 옵트인.
- **새 파라미터** (BridgeMessages ↔ bridge/types.ts, BARE 명시 0 포함):
  - `eyelinerLowerTailTrace` 0..1 — 라인 세로 중심을 lash→삼각존 하단으로 램프(0.40→코너 완만 하강, 코너 후 수평 유지)
  - `eyelinerLowerTailLen` 0..1 — 연장 캔버스로 뻗는 비율(끝 뾰족 테이퍼)
- **삼각존 연동**: 트레이스 활성 시 삼각존 채움이 가로=라이너 꼬리 끝, 세로=디태치 라인 바로 아래까지 확장(쐐기 충전). 트레이스 0이면 전부 기존과 바이트 동일.
- **UI**: 상세 → 아이라인 하 → 핏 축 `꼬리 트레이스`/`꼬리 연장` 슬라이더.
- **분석 연동**: `deriveFitDeltas` E-7(둥근 눈, openness high) → 윙 길이+ 에 더해 트레이스 0.55/연장 0.45 세트(δ 스케일은 계약 D-4/D-5에 따라 기본 OFF).

## 4. 팀원이 알아야 할 계약 변경

1. **§16b 와이드 마스크(2:1)** = 눈+연장(u 0..2) 커버 + **밴드 꼬리 스윕 자동 비활성**.
2. **하부 섀도 마스크 룩**은 잎에 `eyeshadowLowerMaskImported: 1`만 있으면 됨(shape 명시 불필요 — profile 6 자동). 명시 shape는 존중됨.
3. **하부 밴드 `along>1` = 눈꼬리 밖 연장 구간**. 새 하부 셰이더 텀을 추가할 땐 연장 게이트를 반드시 고려할 것(기본은 눈 구간 정지 권장).
4. **profile 0(기본 언더 밴드) 모양이 바뀜** — 사각 밴드 → lash 밀착 스머지. 언더가 예전보다 좁아 보이면 이것 때문(의도).
5. **아래 라이너 텍스처 enum에 3=리퀴드 추가**, 기본값. 시드는 RN·cginc 양쪽 미러 유지 필수.
6. **라이너 콜르아트(liner_*.png) 계약**: 윙 모양·상승은 텍스처가 전부 결정(지오메트리는 직선 캔버스). 스타일 조정은 `scripts/generate-eyeshadow-masks.py` 숫자만.
7. BARE에 `eyelinerLowerTailTrace/TailLen` 명시 0 추가(생략 필드 잔존 규약).

## 5. 빌드·디버깅 노하우 (오늘 확립)

- Unity 소스/StreamingAssets와 네이티브 Pod 입력이 실제로 함께 변경된 전체 Unity 통합 빌드에서만 `scripts/unity/build_ios_unity_framework.sh` 재익스포트 후 `pod install`을 고려한다. Seojin 최소 증분 Release, React Native/TypeScript/backend 변경, 기존 UnityFramework 재사용 시에는 `pod install`을 실행하지 않는다. Pod sandbox mismatch가 나도 자동 재생성하지 말고 임시 변경을 원복한 뒤 정확한 입력 변경을 먼저 확인한다.
- 밴드 지오메트리는 파이썬 래스터 하네스로 빌드 전 검증 가능(접힘·역행·UV 왜곡을 수치+그림으로 재현). 세션 스크래치 `liner_raster.py` 참조 — 필요하면 repo로 옮길 것.
- 기기 로그: `pymobiledevice3 syslog live --match aura`(앱 재시작 불필요). 브리지 페이로드는 `<private>` — 값 확인은 RN 컴파일 jest 프로브로.
- RN만 바뀌면 리빌드 불필요(Metro). 맥 IP가 바뀌면 개발서버 오류 → 리빌드(ip.txt 갱신) 또는 Dev Menu Configure Bundler.
