# AURA 롱 스크롤 홈 — 최종 구현 기준

## 1. 고정 영역

홈 상단의 다음 영역은 기존 디자인과 동작을 유지한다.

1. 기존 4장 이미지 히어로 배너
2. 기존 8개 기능 바로가기
3. 기존 추천 메이크업 필터
4. 현재 승인된 추천 제품 모듈

히어로는 기존 WebP, 문구, 그라데이션, 페이지 표시, 자동 넘김, 클릭 동작을 그대로 사용한다. AURA딘 슬라이드는 AURA딘 검색으로 연결한다. 8개 바로가기의 아이콘, 순서, 간격, 목적지도 변경하지 않는다.

## 2. 홈 편집 원칙

- 화면은 흰 배경과 넉넉한 수직 여백을 중심으로 구성한다.
- 작은 영문 eyebrow와 긴 홍보 문장은 사용하지 않는다.
- 섹션 제목은 짧은 한글 한 줄을 원칙으로 한다.
- 기능 모듈은 장식용 목업 화면이 아니라 해당 기능과 연결된 이미지로 구성한다.
- 모든 기능 카드는 상단 8개 바로가기와 같은 실제 기능 진입 경로를 사용한다.
- 홈에는 룩톡·커뮤니티 모듈을 노출하지 않는다.
- 추천 제품 모듈은 현재 디자인, 데이터 매핑, 클릭 동작을 유지한다.

## 3. 모듈 순서와 동작

모듈 설정의 기준은 `apps/mobile/src/features/home/config/homeModuleRegistry.ts`이다.

| 순서 | 모듈 | 이미지 | 클릭 결과 |
| --- | --- | --- | --- |
| 1 | `faceAnalysis` | 20대 가상 모델과 얼굴 랜드마크를 담은 AI 진단 전용 WebP | AI 얼굴 진단 안내 |
| 2 | `products` | 실제 카탈로그 제품 이미지 | 제품 상세 또는 추천 제품 목록 |
| 3 | `makeupRecommendation` | 서로 다른 인물과 장면으로 상황별 메이크업을 보여주는 전용 WebP 3장 | 메이크업 추천 |
| 4 | `makeupExtraction` | 레퍼런스 얼굴에서 눈·볼·입술 컬러가 분해되는 전용 WebP | 기존 메이크업 추출 액션 시트 |
| 5 | `auradin` | 전용 오로라 글래스 WebP 썸네일 | AURA딘 검색 |
| 6 | `makeupFeedback` | 셀피에 점수 링과 부위별 평가가 표시되는 전용 WebP | 기존 메이크업 피드백 액션 시트 |
| 7 | `consulting` | 컨설팅 기능에서 사용하는 운영 이미지 | 컨설팅 탭 |

룩톡·커뮤니티는 홈 feature ID, registry, feed, renderer에 포함하지 않는다.

## 4. 실제 데이터 계약

### 추천 제품

- `getSeasonalRecommendations(undefined, 8)`의 실제 `CatalogProduct`만 사용한다.
- 판매 중이고 제품명·브랜드·원격 이미지가 있는 항목만 노출한다.
- 내부 catalog ID는 제품 상세로, 외부 catalog ID는 추천 목록으로 연결한다.
- 브랜드, 제품명, 가격, 제휴 표시는 서버 값을 그대로 사용한다.

### 얼굴 분석

- 홈 카드는 최근 분석 결과나 사용자의 얼굴을 보여주는 결과 카드가 아니다.
- 실제 사용자 사진·퍼스널컬러·얼굴형 결과 문구로 썸네일을 교체하지 않는다.
- `face-analysis-diagnosis-v2.webp`의 가상 20대 모델과 얼굴 랜드마크를 항상 사용한다.
- 코드 텍스트는 `AI 얼굴 진단`, `AI로 알아보는 내 얼굴형과 비율`, `AI 진단 시작하기`로 기능 진입 목적을 명확히 한다.
- 카드 전체를 누르면 8개 바로가기와 동일한 얼굴 진단 안내 및 촬영 흐름으로 이동한다.

### 오늘의 메이크업 추천

- 상황을 먼저 고르고 얼굴 분석을 바탕으로 맞춤 메이크업 이미지를 확인하는 기능임을 홈에서 짧게 설명한다.
- 홈 썸네일은 `데이트`, `야구장 전광판`, `로판 여주` 세 상황을 서로 다른 얼굴형, 헤어, 표정, 조명, 의상, 배경으로 구분한다.
- 카탈로그와 추천 기능 내부 구현은 홈 범위에서 수정하지 않는다.
- 이미지에는 문구·라벨·점수·UI를 굽지 않는다. 상황 라벨, 설명, CTA는 접근 가능한 실제 텍스트로 올린다.
- 1+2 벤토 배치 전체를 누르면 기존 `makeupRecommendation` 경로로 이동한다.

### 메이크업 추출

- 연예인 화보나 얼굴 사진에서 눈·볼·입술 컬러를 추출하고 바르는 순서를 설명하는 기능이다.
- 추출된 색상과 부위 연결을 표현한 전용 WebP를 사용하며, 가짜 결과 화면이나 글자를 이미지에 굽지 않는다.
- 카드 전체를 누르면 기존 카메라·앨범 선택 액션 시트를 연다.

### 메이크업 피드백

- 사용자의 얼굴 사진이나 앨범 사진을 분석해 점수, 잘한 점, 보완할 점을 제공하는 기능이다.
- 자연스러운 셀피와 점수 링·부위별 평가 포인트를 표현한 전용 WebP를 사용한다.
- 카드 전체를 누르면 기존 카메라·앨범 선택 액션 시트를 연다.

### AURA딘

- 참고 비주얼을 바탕으로 제작한 전용 오로라 글래스 WebP를 사용한다.
- 이미지에는 문구나 UI를 굽지 않고, 접근 가능한 실제 텍스트를 코드로 올린다.
- `컬러·제형·예산` 조건으로 제품을 비교·탐색하는 기능을 명확히 설명한다.
- 카드의 모든 영역은 AURA딘 검색으로 연결한다.

## 5. 레이아웃 기준

- 홈 모듈 좌우 inset: `20`
- 추천 필터와 첫 모듈 사이: 넉넉한 대형 간격
- 모듈 사이: 최소 `56`
- 제목과 콘텐츠 사이: `20`
- 섹션 제목: 큰 한글 Bold
- 모듈 카드는 이미지가 주인공이 되도록 불필요한 설명과 배지를 제거한다.
- 가로 rail은 다음 카드가 일부 보이게 하여 스크롤 가능성을 알린다.
- 이미지 영역은 고정 크기를 유지해 로딩 중 레이아웃 이동을 막는다.

## 6. 내비게이션 계약

표현 컴포넌트는 라우트 이름을 직접 사용하지 않고 `HomeFeatureId + HomeFeaturePressPayload`만 방출한다. 중앙 분기는 `homeFeatureRouteMap.ts`와 `homeRoutes.tsx`에서 처리한다.

- 얼굴 분석: `faceAnalysis`
- 메이크업 추천: `makeupRecommendation`
- 메이크업 추출: `makeupExtraction`
- 메이크업 피드백: `makeupFeedback`
- AURA딘: `auradin`
- 컨설팅: `consulting`
- 제품: 실제 `itemId`, `shadeId`, 제휴 표시 context

## 7. 이미지 로딩과 스크롤 성능

기존 `expo-image` 메모리·디스크 캐시와 WebP 구조는 유지한다. 롱 스크롤의 모든 이미지를 앱 실행 시 한꺼번에 prefetch하지 않는다.

1. 앱 시작 시 히어로 첫 장만 미리 디코딩한다.
2. 나머지 히어로 이미지는 비활성 슬라이드에서 낮은 우선순위로 로드한다.
3. 추천 필터는 상호작용이 끝난 뒤 첫 2장만 준비한다.
4. 현재 홈 모듈은 대표 이미지 최대 2장을 prefetch한다.
5. 다음 모듈은 대표 이미지 1장만 preview한다.
6. 동시 prefetch 수는 최대 2개다.
7. 화면 밖 모듈은 이미지 source를 넘기지 않고 고정 placeholder를 그린다.
8. 같은 원격 URI는 중복 요청하지 않으며, 실패한 URI는 재노출 시 재시도할 수 있다.
9. 추천 필터와 홈 모듈은 동일한 2-slot prefetch queue를 사용한다.
10. 번들 WebP는 네트워크 요청 대신 노출 단계에서 `loadAsync`로 디코딩한다.
11. 지나간 모듈은 다시 `deferred`로 내려 decoded bitmap 보유를 줄이며, 실제 로드 실패 시 고정 크기 fallback을 표시한다.

세로 홈은 `FlatList`로 유지하고 가로 rail도 작은 초기 렌더 수, 제한된 batch, `getItemLayout`을 사용한다. 히어로 자동 넘김은 홈이 포커스 상태이고 앱이 활성 상태이며 히어로가 화면에 보일 때만 실행한다.

## 8. 로딩·빈 상태·검증

- 제품 API가 비거나 실패하면 로컬 제품 mock을 만들지 않고 추천 제품 진입만 표시한다.
- 홈은 얼굴 분석 보고서나 사용자 얼굴 이미지를 조회하지 않고 AI 얼굴 진단 기능 패널을 항상 유지한다.
- pull-to-refresh는 홈 데이터, 추천 필터와 제품 feed를 갱신한다.
- 룩톡·커뮤니티 카드, 영문 eyebrow, 가짜 결과 화면이나 기능과 무관한 목업 에셋이 registry와 renderer에 없어야 한다.
- 각 기능 모듈은 해당 기능의 기존 목적지로 이동해야 한다.
- 모바일 변경 후 typecheck와 홈 계약 테스트를 통과해야 한다. iOS Metro bundle과 실기기 실행은 사용자가 요청한 최종 검증 시점에만 수행한다.
