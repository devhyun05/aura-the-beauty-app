# 목표 작업 상세 지침

## 공통 작업 규칙

- 저장소 루트의 `AGENTS.md`를 먼저 읽고 따른다.
- `docs/mobile/FRONTEND_WORK_GUIDE.md`를 먼저 읽고 따른다.
- `apps/mobile` 중심으로만 작업한다.
- 새 라이브러리 추가 금지.
- `package.json` / lockfile 변경 금지.
- backend, Unity, ARKit/ARCore, 실제 API 구현 금지.
- 로컬 변경사항이 있으면 임의로 덮어쓰지 않는다.
- TypeScript `any` 사용 금지.
- Tamagui와 기존 `shared/theme`, `shared/ui` 패턴을 따른다.
- 이미지 경로는 mock 데이터에서 관리하고 화면 컴포넌트에 직접 하드코딩하지 않는다.
- 화면 컴포넌트 안에 mock/service/type을 직접 박지 않는다.
- 모바일 기준 402 x 874에서 텍스트, 카드, 이미지가 겹치거나 잘리지 않게 한다.

## 공통 UI 방향

- 전체 UI는 블랙&화이트 중심의 프로페셔널 K-beauty tech 톤으로 만든다.
- 현재 UI가 토이사이트처럼 보이지 않도록 여백, 라인, 폰트 크기, 카드 비율을 정돈한다.
- 과한 핑크, 유아틱한 테두리, 장난감 같은 카드 느낌을 피한다.
- 옅은 핑크는 이미지, 하트, 아주 약한 보조 포인트로만 제한한다.
- 메이크업 스타일 카드의 바깥 핑크 테두리처럼 유아틱하게 보이는 요소는 제거한다.
- 첨부 레퍼런스의 구조는 참고하되, 그대로 따라 하기보다 더 성숙하고 미니멀한 블랙&화이트 앱 화면으로 다듬는다.

## 선행 작업

현재 `feature/analysis-result-detail` 브랜치에 남아있는 UI 톤 개선 변경사항을 확인한다.

1. `apps/mobile` 기준 `npm run typecheck`를 실행한다.
2. 통과하면 다음 커밋을 남긴다.
   - `fix: 마이페이지 분석 결과 UI 톤 개선`
3. 이 커밋을 포함한 HEAD를 아래 3개 브랜치의 공통 베이스로 사용한다.
4. 필요하면 `feature/analysis-result-detail`도 push한다.

## 브랜치 전략

- 아래 3개 브랜치는 UI 톤 개선 커밋을 포함한 최신 HEAD에서 각각 새로 만든다.
- 세 브랜치의 기능 변경이 서로 섞이지 않게 독립적으로 작업한다.
- 각 브랜치 완료 후 `apps/mobile` 기준 `npm run typecheck`를 실행한다.
- 각 브랜치마다 기능 단위 커밋을 남기고 GitHub 원격에 push한다.

## 1. `feature/makeup-look`

마이페이지의 “메이크업 스타일” 섹션에서 “전체보기”를 누르면 “메이크업 룩” 전체 페이지로 이동하도록 구현한다.

요구사항:

- 기존 마이페이지 메이크업 스타일 카드와 전체 페이지가 같은 mock/service/type 데이터를 사용한다.
- mock 데이터는 10개 이상으로 확장한다.
- 부족한 이미지는 새 mock 이미지를 만든다.
- 이미지는 실제 K-beauty 메이크업 룩 카드처럼 보여야 하며 단순 색상 박스나 placeholder는 금지한다.
- 카드 외곽의 과한 핑크 테두리는 금지한다.
- 저장 아이콘은 누르면 저장/해제 상태가 바뀌는 mock UI 동작을 구현한다.
- 카드 터치 시 상세 페이지는 아직 만들지 않는다.
- 한 페이지에 5개씩 표시한다.
- 페이지네이션은 실제 페이지 이동이 되게 만든다.
- 빈 데이터 상태를 준비한다.

커밋 예시:

- `feat: 메이크업 룩 전체보기 화면 추가`
- `refactor: 메이크업 룩 mock 데이터 분리`

## 2. `feature/product-like`

마이페이지의 “좋아요한 제품목록” 섹션에서 “전체보기”를 누르면 “좋아요 목록” 전체 페이지로 이동하도록 구현한다.

요구사항:

- 기존 마이페이지 좋아요 제품 카드와 전체 페이지가 같은 mock/service/type 데이터를 사용한다.
- mock 데이터는 10개 이상으로 확장한다.
- 브랜드명, 제품명, 가격은 유지한다.
- 추가 mock 데이터는 임의로 자연스럽게 작성한다.
- 부족한 제품 이미지는 실제 화장품 제품처럼 보이는 고퀄리티 로컬 asset으로 만든다.
- 단순 색상 박스나 대충 만든 placeholder는 금지한다.
- 상품 카드 터치 시 상세 페이지는 아직 만들지 않는다.
- 하트를 누르면 좋아요 해제 mock 동작을 구현하고 해당 상품은 목록에서 사라지게 한다.
- 한 페이지에 5개씩 표시한다.
- 페이지네이션은 실제 페이지 이동이 되게 만든다.
- 빈 데이터 상태를 준비한다.

커밋 예시:

- `feat: 좋아요 제품 전체보기 화면 추가`
- `feat: 좋아요 제품 해제 mock 동작 추가`
- `refactor: 좋아요 제품 mock 데이터 분리`

## 3. `feature/profile-editor`

마이페이지의 점 세개 설정 버튼을 누르면 “프로필 수정” 화면으로 이동하도록 구현한다.

요구사항:

- 기존 profile mock/service/type과 자연스럽게 연결한다.
- 실제 저장/API 기능은 구현하지 않는다.
- 입력값은 화면 내부 mock state로만 수정 가능하게 한다.
- 사진 업로드는 실제 파일 선택 없이 UI만 구현한다.
- 필드는 이름, 닉네임, 전화번호, 이메일, 생년월일, 성별, 관심사를 사용한다.
- 각 필드는 행 구조로 보여주고 연필 버튼 UI를 제공한다.
- 새 아이콘 라이브러리 추가 금지.
- 로그아웃은 가벼운 mock 동작을 넣는다.
- 회원 탈퇴는 아직 버튼 UI만 구현한다.
- 뒤로가기 가능해야 한다.

커밋 예시:

- `feat: 프로필 수정 화면 추가`
- `feat: 프로필 수정 mock 입력 동작 추가`

## 공통 navigation 요구사항

- 현재 프로젝트가 `AppRoot` screen state 방식이면 기존 방식에 맞춰 최소 수정한다.
- React Navigation을 새로 크게 도입하지 않는다.
- `UserPageScreen`에는 필요한 콜백만 최소 추가한다.
- 기존 분석 결과 목록/상세 플로우는 깨뜨리지 않는다.

## 공통 asset 요구사항

- 새 이미지는 `apps/mobile/src/assets/images` 하위의 적절한 폴더에 저장한다.
- 이미지 경로는 mock 데이터에서 관리한다.
- 화면마다 이미지 require를 직접 반복하지 않는다.
- 이미지 퀄리티는 기존 GPT 생성 asset 수준에 맞춘다.
