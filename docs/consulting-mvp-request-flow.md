# Consulting MVP Request Flow

## Goal

컨설팅 MVP는 AURA가 직접 예약·결제 플랫폼처럼 동작하지 않도록 범위를 낮춘다. 앱은 사용자의 상담 신청을 접수하고, 운영팀이 섭외된 프리랜서와 가능 여부를 확인한 뒤 확정 안내를 보내는 구조로 운영한다.

## Product Boundary

- 네이버 지역 업체는 `Naver Local Search API` 결과를 읽기 전용으로 보여준다.
- 네이버 업체 정보는 앱 DB에 저장하거나 크롤링하지 않는다.
- 네이버 업체에 대한 앱 내 예약, 결제, 확정 처리는 제공하지 않는다.
- AURA 온라인 컨설팅은 직접 섭외한 프리랜서에게만 신청을 보낼 수 있다.
- 앱은 예상가를 표시만 하고 결제, 멤버십, 자동 갱신, 환불 처리는 이번 MVP에서 제외한다.
- 프리랜서와 사용자가 외부에서 비용 정산과 일정을 합의한 뒤, 프리랜서 또는 운영자가 웹에서 예약 확정을 누른다.

## User Flow

1. 사용자는 컨설팅 홈에서 온라인 컨설팅 신청 또는 근처 뷰티샵 찾기를 선택한다.
2. 근처 뷰티샵 찾기는 헤어, 메이크업, 퍼스널컬러, 패션 골격진단 카테고리를 네이버 검색 결과로 표시한다.
3. 사용자는 지역 프리셋, 직접 입력, 현재 위치 기반 검색으로 업체를 탐색한다.
4. 네이버 업체는 네이버 지도/예약 확인 또는 전화 연결로 외부에서 확인한다.
5. 앱 안에서 직접 예약 가능한 대상은 직접 섭외한 프리랜서뿐이다.
6. 온라인 컨설팅은 프리랜서, 희망 일정, 고민, 공유 리포트, 연락처를 입력한다.
7. 앱은 `requested` 상태의 신청을 저장한다.
8. 운영팀이 프리랜서와 일정을 확인하며 상태를 `contacting`, `confirmed`, `unavailable`, `canceled`, `completed`로 변경한다.
9. `confirmed` 이후 앱 대화방과 통화 진입을 활성화한다.

## Backend Notes

- `POST /api/consulting/bookings`는 결제 없이 신청만 생성한다.
- `GET /api/consulting/local-places`는 네이버 Local Search API를 호출하고 결과를 저장하지 않는다.
- 네이버 Local Search API는 `display` 최댓값이 5이고 `start` 최댓값이 1이므로, 카테고리별 검색어 변형을 여러 번 호출해 최대 15개까지 모은다.
- 네이버 Local Search API 응답에는 업체명, 카테고리, 설명, 주소, 좌표, 상세 URL이 포함되지만 평점·사진·가격표·예약 가능 시간은 직접 제공되지 않는다.
- API의 `link`가 업체 홈페이지나 블로그로 내려올 수 있으므로, 앱은 업체명+주소+좌표로 네이버 지도 검색 URL을 만들어 주 CTA로 사용한다.
- 현재 위치 기반 검색은 네이버 API의 반경 검색이 아니라, 기기 좌표와 API 좌표 사이 거리를 계산해 정렬하는 방식이다.
- `PATCH /api/consulting/admin/bookings/{booking_id}/status`로 운영자가 신청 상태를 변경한다.
- 같은 프리랜서의 시간 충돌 방지는 `contacting`, `confirmed` 상태에만 적용한다. 단순 접수(`requested`)끼리는 운영 조율 전 단계라 겹칠 수 있다.
- 기존 결제·멤버십 API는 모바일 플로우에서 제거한다.

## Legal/Operations Caveat

이 문서는 법률 자문이 아니다. 사업자등록, 통신판매, 중개, 유료 결제, 개인정보/문자 발송 요건은 실제 운영 전에 전문가 또는 관할 기관 확인이 필요하다.

MVP의 안전한 운영 원칙:

- AURA는 앱 안에서 결제를 받지 않고, 수수료·환불·정산 책임을 표시하지 않는다.
- AURA는 네이버 등록 업체 정보를 크롤링하거나 자체 업체 DB처럼 영구 저장하지 않는다.
- AURA는 직접 섭외한 프리랜서의 상담 신청만 접수하고, 확정 전까지는 `requested` 또는 `contacting` 상태로 둔다.
- 사용자가 보는 가격은 "표시용 예상가"이며 결제 요청, 영수증, 환불 약속으로 표현하지 않는다.
- 프리랜서가 사용자와 외부에서 비용과 일정을 합의한 뒤 웹에서 `confirmed` 상태로 바꾼다.
- 실제 반복 영업, 수수료 수취, 결제 대행, 광고 상품, 유료 멤버십을 열 경우 사업자등록·통신판매업·통신판매중개 책임 검토가 필요하다.
