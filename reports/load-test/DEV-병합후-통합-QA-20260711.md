# DEV 병합 후 통합 QA 결과

## 결론

`origin/dev`의 최신 변경을 `feature/jun-lamb`에 병합한 현재 코드는 병합 가능한 상태다.
dev에 있던 API, DB 테이블, 모바일 서비스 내보내기 항목 중 병합 후 사라진 항목은 없었다.
서버 비동기 처리 구조와 dev의 인증·미디어·계정·상담·헤어 기능도 함께 유지됐다.

단, 현재 AWS dev API는 아직 병합 전 이미지로 실행 중이다. 이 문서의 전체 코드 QA 결과는 PR 병합 후 새 이미지를 배포해야 실제 서비스에 반영된다.

## 이번 QA에서 찾아 고친 내용

### 파트너 API 인증 충돌

기존 API Gateway의 `ANY /{proxy+}` Cognito JWT 규칙이 상담사 웹의 자체 세션 토큰까지 차단하고 있었다.
`/api/consulting/partner/*`만 Gateway Cognito 검사를 건너뛰고 FastAPI의 파트너 세션 검사가 담당하도록 분리했다.

- 잘못된 로그인 입력은 FastAPI까지 도달해 `422`
- 세션 없는 파트너 업무 API는 `401`
- 기존 Cognito 보호 API도 토큰 없이는 계속 `401`
- 로그인은 초당 5회, 입점 신청은 초당 2회로 Gateway 제한 적용

### iOS 사진 저장 권한 누락

추천 이미지를 사진 앱에 저장하지만 네이티브 `Info.plist`에 `NSPhotoLibraryAddUsageDescription`이 없었다.
한국어 권한 문구를 반영하고, `app.json`과 네이티브 설정이 다시 어긋나면 모바일 CI에서 실패하도록 검사를 추가했다.

### 완료되지 않은 업로드 이미지 정리

업로드 URL을 받은 뒤 파일만 S3에 올리고 완료 API를 호출하지 못하면 DB에는 만료 세션, S3에는 고아 이미지가 남을 수 있었다.
30분 정리 작업이 만료된 세션의 원본, Lambda 썸네일, 앱 업로드 썸네일을 삭제한 뒤 DB를 `expired`로 바꾸도록 보완했다.
삭제가 실패하면 세션을 `pending`으로 유지해 다음 실행에서 재시도한다.

### Lambda 로그 보존

이미지 후처리 Lambda 로그가 무기한 보존되던 설정을 14일로 변경했다.
운영 알람 재설정 스크립트에도 같은 값을 포함했다.

- S3 퍼블릭 접근 차단과 저장 암호화: 활성

## PR 병합 후 필수 순서

1. 병합 커밋 기준으로 백엔드 Linux 이미지를 새로 빌드한다.
2. DB 스키마 검사를 통과시킨 뒤 ECS API, Worker, 정리 작업의 task definition을 같은 이미지로 갱신한다.
3. ECS 배포 안정화와 ALB `healthy` 상태를 확인한다.
4. iOS에서 로그인, 얼굴 진단, 메이크업 피드백, 레퍼런스 추출, 이미지 저장을 각각 한 번 실행한다.
5. SQS와 DLQ가 비고 Lambda·Worker·API 로그에 오류가 없는지 확인한다.

## 남은 운영 전 항목

- 현재 RDS는 퍼블릭 접근 가능 설정이지만 팀원 IP 두 개와 ECS 보안그룹만 5432 접근이 허용된다. 운영 환경에서는 사설 서브넷으로 이전해야 한다.
- Expo Doctor 기준 Expo 56 패치 버전 차이 6개가 남아 있다. 이번 서버 병합 PR의 잠금 파일 충돌을 피하기 위해 포함하지 않았으며 iOS Release 전 별도 의존성 정리로 처리한다.
- 네이티브 iOS 폴더를 직접 관리하므로 `expo prebuild`를 무심코 실행하면 Unity와 Release 설정을 덮어쓸 수 있다. 현재 추가한 CI 계약 검사를 유지해야 한다.
- 화상상담은 아직 구현 대상에서 제외했다. 관련 기능이 들어오면 별도 Worker 분리 여부와 실시간 통신 인프라를 다시 검토한다.
